PART 5 ROS 2 연동과 시뮬레이션 · 약 45분

17ros2_control과 실기 하드웨어 인터페이스

Feetech 버스를 ros2_control SystemInterface로 감싸 실제 팔을 ROS 2에서 제어합니다.

시뮬레이터 열기 명령어 생성기

ros2_control의 구조#

ROS 2에서 실제 하드웨어를 제어하는 표준 프레임워크입니다. 세 층으로 나뉩니다.

text
┌─────────────────────────────────────────┐
│  컨트롤러 (Controller)                   │  joint_trajectory_controller
│  "이 궤적대로 움직여라"                    │  joint_state_broadcaster
├─────────────────────────────────────────┤
│  컨트롤러 매니저 (Controller Manager)      │  제어 주기마다 read() → update() → write()
├─────────────────────────────────────────┤
│  하드웨어 인터페이스 (SystemInterface)      │  so_arm_hardware
│  "시리얼로 서보에 명령을 쓰고 상태를 읽는다"  │
└─────────────────────────────────────────┘
                    ↓ USB 시리얼 (SCS 프로토콜)
              STS3215 × 6

핵심은 컨트롤러가 하드웨어를 모른다는 점입니다. 같은 joint_trajectory_controller가 Mock에서도, Gazebo에서도, 실물에서도 동일하게 동작합니다. 바뀌는 것은 맨 아래 하드웨어 인터페이스뿐입니다.

하드웨어 타입 전환#

xacro 인자 하나로 세 가지 모드를 전환합니다.

hardware_type플러그인용도
mockmock_components/GenericSystem하드웨어 없이 테스트
gazebogz_ros2_control/GazeboSimSystem물리 시뮬레이션 (19장)
realso_arm_hardware/SOArmHardware실물 SO-ARM101

ros2_control xacro#

xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro">

  <xacro:macro name="so101_ros2_control"
               params="name hardware_type usb_port baud_rate:=1000000">
    <ros2_control name="${name}" type="system">

      <!-- ── 하드웨어 플러그인 선택 ───────────────────────── -->
      <xacro:if value="${hardware_type == 'mock'}">
        <hardware>
          <plugin>mock_components/GenericSystem</plugin>
          <param name="calculate_dynamics">true</param>
        </hardware>
      </xacro:if>

      <xacro:if value="${hardware_type == 'gazebo'}">
        <hardware>
          <plugin>gz_ros2_control/GazeboSimSystem</plugin>
        </hardware>
      </xacro:if>

      <xacro:if value="${hardware_type == 'real'}">
        <hardware>
          <plugin>so_arm_hardware/SOArmHardware</plugin>
          <param name="usb_port">${usb_port}</param>
          <param name="baud_rate">${baud_rate}</param>
          <param name="torque_enable">true</param>
        </hardware>
      </xacro:if>

      <!-- ── 조인트 정의 ────────────────────────────────── -->
      <xacro:so101_joint name="shoulder_pan"  id="1" min="-1.91986"  max="1.91986"  offset="0"/>
      <xacro:so101_joint name="shoulder_lift" id="2" min="-1.74533"  max="1.74533"  offset="0"/>
      <xacro:so101_joint name="elbow_flex"    id="3" min="-1.69"     max="1.69"     offset="0"/>
      <xacro:so101_joint name="wrist_flex"    id="4" min="-1.65806"  max="1.65806"  offset="0"/>
      <xacro:so101_joint name="wrist_roll"    id="5" min="-2.74385"  max="2.84121"  offset="0"/>
      <xacro:so101_joint name="gripper"       id="6" min="-0.174533" max="1.74533"  offset="0"/>

    </ros2_control>
  </xacro:macro>

  <xacro:macro name="so101_joint" params="name id min max offset">
    <joint name="${name}">
      <command_interface name="position">
        <param name="min">${min}</param>
        <param name="max">${max}</param>
      </command_interface>
      <state_interface name="position"/>
      <state_interface name="velocity"/>
      <state_interface name="effort"/>
      <param name="servo_id">${id}</param>
      <param name="position_offset">${offset}</param>
    </joint>
  </xacro:macro>

</robot>
`position_offset` 이 핵심입니다

서보의 중위(2048)와 URDF의 0 rad가 정확히 일치하지 않으면 RViz 자세와 실제 자세가 어긋납니다. 이 오프셋 값(서보 틱 단위)으로 보정합니다. 아래 "자세 불일치 보정"에서 다룹니다.

컨트롤러 설정#

config/controllers.yaml:

yaml
controller_manager:
  ros__parameters:
    update_rate: 100  # Hz

    joint_state_broadcaster:
      type: joint_state_broadcaster/JointStateBroadcaster

    joint_trajectory_controller:
      type: joint_trajectory_controller/JointTrajectoryController

joint_trajectory_controller:
  ros__parameters:
    joints:
      - shoulder_pan
      - shoulder_lift
      - elbow_flex
      - wrist_flex
      - wrist_roll
      - gripper
    command_interfaces:
      - position
    state_interfaces:
      - position
      - velocity
    state_publish_rate: 50.0
    action_monitor_rate: 20.0
    allow_partial_joints_goal: false
    constraints:
      stopped_velocity_tolerance: 0.05
      goal_time: 0.5
그리퍼를 별도 컨트롤러로 두지 않습니다

원문 위키 구성에서도 gripper_controller는 제거되었고, **joint_trajectory_controller가 6개 관절 전체를 제어**합니다. MoveIt 설정도 여기에 맞춰야 합니다.

실기 구동#

1) 컨트롤러 단독 실행#

bash
ros2 launch so_arm101_description controllers_bringup.launch.py \
  hardware_type:=real \
  usb_port:=/dev/ttyACM0

so_arm_hardware 플러그인이 자동으로 다음을 수행합니다.

  1. 시리얼 포트를 엽니다.
  2. 서보 ID 1~6을 스캔합니다.
  3. 각 서보가 응답하는지 검증합니다.
  4. 토크를 활성화하고 현재 위치를 읽습니다.
토크가 켜지는 순간

토크가 활성화되면 팔이 현재 위치를 유지하려고 힘을 줍니다. 팔이 중력으로 처져 있었다면 그 자세를 그대로 유지합니다. 실행 전에 팔을 안정적인 자세(예: rest)로 두세요.

2) MoveIt까지 한 번에#

bash
ros2 launch so_arm101_moveit_config demo.launch.py \
  hardware_type:=real \
  usb_port:=/dev/ttyACM0

demo.launch.py는 컨트롤러 스택을 내부에 포함하고 있습니다.

두 방식을 동시에 실행하지 마세요

1)번을 이미 실행 중이라면 반드시 종료한 뒤 2)번을 실행하세요. 컨트롤러 매니저가 두 개 뜨면 충돌합니다.

1)번을 쓴 경우 MoveIt 추가 실행#

bash
# 터미널 2 — move_group
ros2 launch so_arm101_moveit_config move_group.launch.py

# 터미널 3 — RViz
ros2 launch so_arm101_moveit_config moveit_rviz.launch.py

자세 불일치 보정#

RViz에 표시되는 자세가 실제 팔과 다를 때 (관절 오프셋, 잘못된 충돌 경고 등) 다음 순서로 잡습니다.

1) 서보 중위 캘리브레이션 확인#

먼저 5장의 서보 중위 캘리브레이션이 제대로 되었는지 확인합니다. 이것이 안 되어 있으면 오프셋으로 아무리 보정해도 가동범위가 비대칭으로 남습니다.

2) position_offset 조정#

so101.ros2_control.xacro에서 해당 조인트의 position_offset을 수정합니다.

환산 공식
text
새 offset = 현재 offset + (RViz에 표시된 오차 rad ÷ 0.00153398)

0.00153398 rad는 STS3215의 1틱입니다. (2π ÷ 4096)

예시: elbow_flex가 실제로는 0°인데 RViz에서 0.12 rad로 표시된다면,

text
0.12 ÷ 0.00153398 ≈ 78.2 → 78틱
새 offset = 0 + 78 = 78
xml
<xacro:so101_joint name="elbow_flex" id="3" min="-1.69" max="1.69" offset="78"/>

3) 재빌드#

bash
colcon build --packages-select so_arm101_description --symlink-install
source install/setup.bash

--symlink-install을 썼다면 xacro 수정은 재빌드 없이 반영될 수 있지만, 확실하게 하려면 재빌드하세요.

실습 — 오프셋 잡기
  1. 팔을 손으로 잡아 각 관절이 0°(중립) 이 되도록 맞춥니다.
  2. ros2 topic echo /joint_states --once 로 현재 값을 읽습니다.
  3. 0에서 벗어난 값을 위 공식에 넣어 오프셋을 계산합니다.
  4. xacro 수정 → 재빌드 → 재실행 → 다시 확인.
  5. 모든 관절이 0에 가까워질 때까지 반복합니다.

시리얼 문제 해결#

bash
# 포트 존재 확인
ls -l /dev/ttyACM*

# 권한 확인
groups   # dialout 이 있어야 함

# 임시 권한
sudo chmod 666 /dev/ttyACM0

# 포트를 점유한 프로세스 찾기
sudo lsof /dev/ttyACM0
LeRobot과 동시에 실행할 수 없습니다

lerobot-teleoperate가 돌고 있으면 그 프로세스가 시리얼 포트를 점유합니다. ROS 2 하드웨어 인터페이스가 같은 포트를 열 수 없습니다. 한 번에 하나만 실행하세요.

증상원인해결
Permission denieddialout 그룹 미가입sudo usermod -a -G dialout $USER 후 재로그인
Device or resource busy다른 프로세스가 점유sudo lsof /dev/ttyACM0 로 확인 후 종료
서보 스캔 실패ID 미설정 또는 보레이트 불일치5장 재확인
일부 서보만 인식3핀 케이블 접촉 불량배선 점검
토크 활성화 실패전원 미연결12V 어댑터 확인
포트 번호가 매번 바뀜udev 규칙 없음7장 udev 설정

컨트롤러 운용 명령 모음#

bash
# 컨트롤러 목록과 상태
ros2 control list_controllers

# 하드웨어 인터페이스 목록
ros2 control list_hardware_interfaces

# 컨트롤러 비활성화
ros2 control set_controller_state joint_trajectory_controller inactive

# 컨트롤러 로드 + 활성화 (spawner 사용 권장)
ros2 run controller_manager spawner joint_trajectory_controller

# 컨트롤러 언로드
ros2 control unload_controller joint_trajectory_controller
`load_controller` 를 먼저 쓰지 마세요

ros2 control load_controller를 먼저 실행하면 컨트롤러가 **unconfigured 상태**가 되어, 이후 spawner가 활성화하지 못합니다. 이미 그렇게 했다면 unload_controller로 내린 뒤 spawner로 다시 시작하세요.
