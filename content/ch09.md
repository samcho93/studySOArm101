## 텔레오퍼레이션이란

사람이 **리더 암**을 손으로 움직이면, 그 관절 각도를 읽어 **팔로워 암**에 그대로 명령으로 보내는 것입니다. 구조는 놀랍도록 단순합니다.

```python
while True:
    action = teleop_device.get_action()   # 리더의 현재 관절 각도를 읽는다
    robot.send_action(action)             # 팔로워에게 그 각도로 가라고 명령한다
```

이게 전부입니다. 초당 30~60회 반복하면 팔로워가 리더를 실시간으로 따라옵니다.

:::info 왜 이 단순한 구조가 중요한가
모방학습 데이터셋의 `action`은 바로 이 리더의 관절 각도입니다. 즉 **텔레오퍼레이션을 하는 것 자체가 데이터 수집**입니다. ([11장](~/lessons/ch11.html))
:::

---

@fig[teleop-loop] 리더에서 읽은 각도가 팔로워 명령이면서 동시에 데이터셋의 정답이 됩니다.

## 먼저 시뮬레이터에서 체험하기

실물을 켜기 전에 감을 잡아 두면 사고를 줄일 수 있습니다.

:::task 실습 — 시뮬레이터 텔레오퍼레이션
[3D 시뮬레이터](~/sim/index.html)를 열고 **"텔레오퍼레이션" 탭**을 선택하세요.

1. 화면에 **반투명한 리더 암**과 **불투명한 팔로워 암**이 함께 나타납니다.
2. 슬라이더나 IK 타깃으로 **리더**를 움직이면 팔로워가 약간의 지연을 두고 따라옵니다.
3. **"추종 지연(lag)" 슬라이더**를 올려 보세요. 실제 시리얼 통신 지연과 서보 응답 지연을 모사한 것입니다. 지연이 크면 빠른 동작에서 팔로워가 뒤처지는 것을 볼 수 있습니다.
4. **"조인트 한계 초과 경고"** 를 켜 두면, 리더가 팔로워의 물리적 한계를 넘는 자세를 만들 때 해당 관절이 빨갛게 표시됩니다. 실물에서 이 상황이 바로 서보 과부하입니다.

리더 암 실물이 이미 있다면 슬라이더 대신 **진짜 리더를 꽂아** 움직일 수 있습니다. 바로 아래 절을 보세요.
:::

## 실기 리더 암을 시뮬레이터에 연결하기

팔로워가 아직 없거나, 조립 전에 리더만 먼저 왔다면 — **리더 암을 브라우저에 직접
꽂아 시뮬레이터의 팔을 움직일 수 있습니다.** 리더를 손으로 움직이면 화면 속
팔로워가 똑같이 따라옵니다.

:::info 어떻게 동작하나
[3D 시뮬레이터](~/sim/index.html)가 **Web Serial API** 로 드라이버 보드에 직접
접속해, STS3215 서보 6개의 **현재 위치 레지스터(주소 56)** 를 초당 수십 번 읽습니다.
읽은 틱 값을 라디안으로 바꿔 시뮬레이터의 리더 자세로 넣으면, 나머지는 위에서
본 텔레오퍼레이션 루프와 완전히 같습니다.

프로토콜은 `scservo_sdk` 의 `PacketHandler(0)` 과 같은 **Feetech SMS/STS** 규격이고,
16비트 값은 리틀엔디언입니다. LeRobot 이 파이썬으로 하는 일을 브라우저가 그대로
합니다.
:::

:::tip 서보에 아무것도 쓰지 않습니다
이 연결은 **읽기 전용**입니다. 토크를 켜거나 목표 위치를 보내는 명령을 일절
보내지 않으므로 서보 설정이 바뀌거나 팔이 갑자기 움직일 일이 없습니다.
리더 암은 원래 사람이 손으로 움직이는 입력 장치이므로 읽기만으로 충분합니다.
:::

### 준비물

- 리더 암 + 드라이버 보드 + **5V 6A 전원 어댑터**
- USB-C 케이블
- **Chrome 또는 Edge** (크로미움 계열). Firefox·Safari 는 Web Serial 미지원입니다.
- 페이지를 **`https://` 또는 `localhost`** 로 열 것

:::warn 로컬에서 열 때
`file://` 로 직접 연 페이지에서는 Web Serial 이 차단됩니다. 반드시 로컬 서버로 여세요.

```bash
python build.py --serve
```
:::

### 연결 순서

1. 리더 암에 **전원과 USB** 를 연결합니다.
2. 시뮬레이터를 열고 **텔레오퍼 탭 → 실기 리더 암 연결** 로 갑니다.
3. 보레이트가 **1,000,000** 인지 확인하고 **[리더 암 연결]** 을 누릅니다.
4. 브라우저가 띄우는 포트 목록에서 드라이버 보드를 고릅니다.
   (보통 `CH340` 또는 `USB Serial Device` 로 보입니다)
5. 연결되면 아래 표에 **서보 6개의 틱 값이 실시간으로** 찍히기 시작합니다.

:::warn LeRobot 과 동시에 쓸 수 없습니다
시리얼 포트는 한 번에 한 프로그램만 열 수 있습니다. `lerobot-teleoperate` 가
돌고 있으면 브라우저가 포트를 못 엽니다. 반대도 마찬가지입니다.
한쪽을 끄고 다른 쪽을 여세요. ([17장](~/lessons/ch17.html)에서 같은 이야기가 나옵니다)
:::

### 방향과 영점 맞추기

연결 직후에는 리더의 틱 값과 시뮬레이터 조인트가 어떻게 대응하는지 모릅니다.
맞추는 방법이 두 가지입니다.

**방법 A — 캘리브레이션 JSON 불러오기 (권장)**

[8장](~/lessons/ch08.html)에서 `lerobot-calibrate` 를 이미 돌렸다면, 그 결과 파일을
그대로 쓰면 됩니다.

```text
~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/<내 id>.json
```

**[캘리브레이션 JSON]** 버튼으로 이 파일을 고르면, 각 조인트의 `range_min` ~
`range_max` 를 URDF 조인트 한계에 선형 대응시킵니다. `drive_mode` 까지 읽으므로
**방향도 자동으로 맞습니다.**

**방법 B — 영점 캡처**

캘리브레이션 파일이 없다면, 리더를 **각 관절이 가동범위 한가운데** 오도록 세운 뒤
**[영점 캡처]** 를 누릅니다. 그 자세가 시뮬레이터의 중립 자세가 됩니다.
그다음 관절을 하나씩 움직여 보고, 화면이 **반대로 움직이는 관절만** 표의
`반전` 체크박스를 켜면 됩니다.

### 읽기 속도

표 위의 **읽기 속도**에 실제 달성 주파수가 표시됩니다.

| 표시 | 의미 |
| --- | --- |
| `sync` | SYNC READ — 한 번의 요청으로 6개를 모두 읽습니다. 빠릅니다 |
| `개별` | 서보를 하나씩 읽습니다. SYNC READ 가 3번 실패하면 자동 전환됩니다 |
| `타임아웃 N` | 응답이 없던 횟수. 계속 늘어나면 배선이나 보레이트를 의심하세요 |

50 Hz 정도면 손으로 움직이는 속도를 충분히 따라옵니다. 값이 너무 낮으면
**읽기 주기(Hz)** 를 내려 보세요 — 무리하게 올리면 오히려 타임아웃이 늘어납니다.

:::task 실습 — 실기 리더로 시뮬레이터 움직이기
1. 리더 암만 연결하고 시뮬레이터를 엽니다. (팔로워는 아직 없어도 됩니다)
2. 연결한 뒤 리더를 천천히 움직이며 **반투명한 리더 암**이 따라오는지 봅니다.
3. **추종 지연**을 0 ms 와 300 ms 로 바꿔 가며 불투명한 팔로워가 어떻게
   뒤처지는지 관찰합니다.
4. **녹화 탭**에서 궤적을 기록해 보세요. 실기 리더로 만든 진짜 궤적입니다.

이 상태에서 조인트 한계를 넘기면 해당 관절이 빨갛게 표시됩니다.
**실기 팔로워를 연결하기 전에 리더의 가동 습관을 교정할 좋은 기회입니다.**
:::

### 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| [리더 암 연결] 버튼이 비활성 | Firefox·Safari 또는 `file://` | Chrome/Edge + `localhost` 로 열기 |
| 포트 목록에 아무것도 없음 | 드라이버 미설치 / USB 미연결 | 장치 관리자에서 CH340 인식 확인 |
| 연결은 되는데 전부 "응답 없음" | 전원 미연결 · 보레이트 불일치 · 점퍼 A 채널 | [3장](~/lessons/ch03.html) 배선 확인 |

| 포트를 못 엶 | LeRobot 이 점유 중 | `lerobot-*` 프로세스 종료 |

## 실물 텔레오퍼레이션 실행

### 기본 명령

```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_awesome_follower_arm \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_awesome_leader_arm
```

:::tip 포트 이름은 명령어 생성기로
[명령어 생성기](~/tools/cli-builder.html)에 포트와 id를 입력해 두면 위 명령이 자동 완성됩니다.
:::

### 이 명령이 하는 일

1. 캘리브레이션 파일이 있는지 확인하고, 없으면 **캘리브레이션 절차를 먼저 시작**합니다.
2. 리더와 팔로워를 연결합니다.
3. 텔레오퍼레이션 루프를 시작합니다.

### 파이썬 API 버전

```python
from lerobot.teleoperators.so_leader import SO101Leader, SO101LeaderConfig
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig

robot_config = SO101FollowerConfig(
    port="/dev/ttyACM0",
    id="my_follower_arm",
)

teleop_config = SO101LeaderConfig(
    port="/dev/ttyACM1",
    id="my_leader_arm",
)

robot = SO101Follower(robot_config)
teleop_device = SO101Leader(teleop_config)
robot.connect()
teleop_device.connect()

while True:
    action = teleop_device.get_action()
    robot.send_action(action)
```

## 첫 실행 안전 수칙

:::danger 처음 켤 때 반드시
1. **팔로워 주변을 비우세요.** 반경 60cm 안에 물건·사람·케이블이 없어야 합니다. (최대 도달 반경이 약 48cm입니다)
2. **전원 플러그를 손이 닿는 곳에** 두세요. 이상이 생기면 즉시 뽑을 수 있어야 합니다.
3. **리더를 아주 천천히** 움직이세요. 팔로워가 어떻게 반응하는지 먼저 관찰합니다.
4. 베이스가 **클램프로 고정**되어 있는지 확인하세요.
5. 터미널에서 **Ctrl+C** 로 언제든 멈출 수 있습니다.
:::

### 정상 동작 판정

| 관찰 | 판정 |
| --- | --- |
| 리더를 움직이면 팔로워가 **같은 방향**으로 따라옴 | 정상 |
| 팔로워가 **반대 방향**으로 움직임 | 서보 ID 배치 오류 또는 drive_mode 문제 |
| 팔로워가 **덜덜 떨림** | 전원 용량 부족 또는 통신 지연 |
| 팔로워가 **한 관절만 안 움직임** | 그 관절 캘리브레이션 범위 0 |
| 팔로워가 **급격히 튐** | 캘리브레이션 불일치 — 즉시 정지 |
| 리더가 **손으로 안 움직임** | 리더 토크가 켜져 있음 |

## 그리퍼 동작

리더의 **트리거**를 당기면 팔로워의 **그리퍼가 닫힙니다.** 트리거도 하나의 서보(ID 6)이므로, 다른 관절과 똑같이 각도가 전달됩니다.

:::warn 그리퍼는 힘 제한이 없습니다
STS3215는 위치 제어이므로, 물체를 잡은 상태에서 트리거를 더 당기면 **서보가 계속 힘을 줍니다.** 과도하게 당기면 그리퍼 부품이 깨지거나 서보가 과열됩니다. 물체를 잡는 순간 트리거를 멈추는 감각을 익히세요.
:::

## 시각화와 함께 보기 (`rerun`)

관절 값과 카메라 영상을 실시간 그래프로 보려면 `--display_data=true`를 추가합니다. (카메라 설정은 [10장](~/lessons/ch10.html))

```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_follower_arm \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_leader_arm \
    --display_data=true
```

`rerun` 뷰어가 열리고 각 관절의 목표값(action)과 실제값(observation)이 그래프로 그려집니다.

:::tip 추종 오차 읽기
action과 observation 곡선 사이의 간격이 **추종 오차**입니다. 빠르게 움직일수록 벌어지는데, 이 간격이 크면 데이터셋 품질이 떨어집니다. 데이터 수집 시 **동작 속도를 일정하게, 너무 빠르지 않게** 유지해야 하는 이유입니다.
:::

## 대안 — 리더 암 없이 조종하기

리더 암이 아직 없거나 고장 났다면 다른 입력 장치를 쓸 수 있습니다.

| 방식 | 설명 |
| --- | --- |
| **키보드** | `--teleop.type=keyboard`. 관절을 키로 증감. 정밀하지 않지만 테스트에 유용 |
| **게임패드** | `--teleop.type=gamepad`. 아날로그 스틱으로 관절 제어 |
| **휴대폰** | LeRobot의 [phone_teleop](https://huggingface.co/docs/lerobot/main/en/phone_teleop) — 폰 자세로 팔로워를 제어 |
| **LeLab 웹 UI** | [github.com/huggingface/leLab](https://github.com/huggingface/leLab) — 캘리브레이션·텔레오퍼레이션·녹화·학습·재생을 브라우저 하나로 |
| **ESP32-S3 무선** | 원문 위키의 무선 텔레오퍼레이션 프로젝트 |

:::info 키보드 텔레오퍼레이션 제약
키보드 텔레오퍼레이션은 **전역 키 입력 백엔드**가 필요합니다. X11 세션이나 Windows 데스크톱에서만 동작하며 **Wayland나 헤드리스 환경에서는 불가**합니다.

(녹화 중 에피소드 제어 키 `n`/`r`/`q`는 별개로, 터미널에서 직접 읽기 때문에 Wayland·헤드리스·SSH에서도 동작합니다.)
:::

저장소에 포함된 간단한 키보드 텔레오퍼레이션 예제도 참고하세요.

```bash
python scripts/so101_keyboard_teleop.py --port /dev/ttyACM0 --id my_follower_arm
```
