## 왜 필요한가

STS3215는 **하나의 버스(선 한 줄)에 여러 서보가 매달리는** 구조입니다. 컨트롤러가 "3번 서보, 2048로 가라"고 말하려면 각 서보에 **고유한 ID**가 있어야 합니다.

문제는 **공장 출하 시 모든 서보의 ID가 1**이라는 것입니다. 그대로 연결하면 ID가 6개 전부 충돌해 통신이 깨집니다.

또한 데이터 전송 속도인 **보레이트(baud rate)** 도 컨트롤러와 모든 서보가 동일해야 합니다. SO-ARM101은 **1,000,000 bps(1 Mbps)** 를 사용합니다.

:::warn 원문의 오기 주의
중국어 원문 조립 문서에는 한 곳에 "보레이트 100000"이라고 적혀 있지만, 같은 문서의 다른 곳과 실제 설정 화면은 모두 **一百万 = 1,000,000** 입니다. STS3215의 공장 기본값도 1,000,000 bps 입니다. **1 뒤에 0이 여섯 개**라고 기억하세요.
:::

:::warn 반드시 조립 전에
ID 설정은 **서보를 한 번에 하나씩만** 버스에 연결한 상태에서 해야 합니다. 조립이 끝난 뒤에는 개별 연결이 불가능하므로, ID 설정은 조립 *전*에 끝내야 합니다.
:::

:::info "중위(中位) 캘리브레이션"이라는 말
중국어 자료의 **中位校准**을 그대로 옮긴 표현으로, 우리말로 풀면 **"현재 자세를 그 서보의 중립 위치(기계적 0점, 틱 값 2048)로 기록하는 작업"** 입니다. 이 강좌에서는 널리 쓰이는 **중위 캘리브레이션**을 그대로 쓰되, 뜻은 "중립 위치 보정"으로 이해하시면 됩니다.
:::

이 값들은 서보 내부의 **EEPROM(비휘발성 영역)** 에 기록되므로 **한 번만** 하면 됩니다. 다른 로봇에서 떼어 온 서보를 재활용하는 경우에도 이 과정이 필요합니다.

## 방법 A — LeRobot CLI (권장)

LeRobot 환경이 준비되어 있어야 합니다. ([6장](~/lessons/ch06.html), [7장](~/lessons/ch07.html) 선행)

@fig[servo-id-flow] `lerobot-setup-motors` 가 안내하는 순서. 그리퍼(6번)부터 시작해 어깨(1번)로 거슬러 올라갑니다.

### 팔로워 암

USB 케이블과 전원을 팔로워의 드라이버 보드에 연결한 뒤 실행합니다.

```bash
lerobot-setup-motors \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0
```

파이썬 API로도 같은 일을 할 수 있습니다.

```python
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig

config = SO101FollowerConfig(
    port="/dev/ttyACM0",
    id="my_awesome_follower_arm",
)
follower = SO101Follower(config)
follower.setup_motors()
```

실행하면 다음 안내가 나옵니다.

```text
Connect the controller board to the 'gripper' motor only and press enter.
```

지시대로 **그리퍼 서보만** 보드에 연결합니다. 이 서보가 보드에 연결된 **유일한** 서보여야 하고, 다른 서보와 데이지체인으로 이어져 있어도 안 됩니다. Enter를 누르면 스크립트가 자동으로 ID와 보레이트를 설정합니다.

```text
'gripper' motor id set to 6
Connect the controller board to the 'wrist_roll' motor only and press enter.
```

:::info ID는 6 → 1 역순으로 설정됩니다
`gripper`(6) → `wrist_roll`(5) → `wrist_flex`(4) → `elbow_flex`(3) → `shoulder_lift`(2) → `shoulder_pan`(1) 순서입니다. 방금 설정한 서보의 3핀 케이블은 **보드 쪽만 빼고 서보 쪽은 그대로 두면** 됩니다. 어차피 나중에 그 자리에 쓰입니다.
:::

각 서보마다 같은 과정을 반복합니다.

:::warn Enter를 누르기 전에 매번 케이블을 확인하세요
보드를 만지다 보면 **전원 케이블이 빠지는 일이 자주** 있습니다. 에러가 나면 다음을 점검하세요.

- 전원 어댑터 연결
- PC ↔ 보드 USB 케이블
- 보드 ↔ 서보 3핀 케이블
- (Waveshare 보드) 점퍼 2개가 모두 **B 채널(USB)** 에 있는지
:::

6개를 모두 마치면 스크립트가 종료됩니다. 이제 서보들을 **데이지체인으로 연결**하고, 첫 번째 서보(ID=1, shoulder_pan)의 케이블을 드라이버 보드에 꽂은 뒤 보드를 팔 베이스에 장착합니다.

### 리더 암

동일한 과정을 `teleop` 타입으로 반복합니다.

```bash
lerobot-setup-motors \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1
```

```python
from lerobot.teleoperators.so_leader import SO101Leader, SO101LeaderConfig

config = SO101LeaderConfig(
    port="/dev/ttyACM1",
    id="my_awesome_leader_arm",
)
leader = SO101Leader(config)
leader.setup_motors()
```

:::danger 감속비를 다시 확인하세요
리더 암은 관절마다 **감속비가 다른 서보**를 씁니다. ID를 설정할 때 **어떤 물리 서보에 몇 번을 부여하는지** 반드시 [3장 표](~/lessons/ch03.html)와 대조하세요. 잘못 배치하면 리더가 너무 뻑뻑하거나 팔이 처집니다.
:::

## 방법 B — FD 디버그 툴 (Windows)

Feetech가 배포하는 공식 PC 설정 프로그램입니다. (중국어 자료에서 말하는 "上位机(상위기)"가 바로 이 PC 쪽 설정 툴을 가리킵니다.)

- 다운로드: [gitee.com/ftservo/fddebug](https://gitee.com/ftservo/fddebug)
- `FD1.9.8.5(250729).7z` 같은 파일을 받아 압축을 풀고 내부의 `.exe`를 실행합니다.

### 단계

1. FD 툴을 열고 **COM 포트 번호**를 선택, **보레이트를 1000000**으로 설정한 뒤 **"打开(열기)"** 클릭.
2. **"搜索(검색)"** 클릭 → `STS3215`가 나타나면 **"停止(정지)"** 클릭 후 목록의 `STS3215` 선택.
3. 상단 **"调试(디버그)"** 탭에서 슬라이더를 끌어 서보를 회전시켜 보거나 **"扫描(스캔)"** 으로 왕복 운동을 시켜 정상 동작을 확인합니다.
4. 상단 **"编程(프로그래밍)"** 탭으로 이동.
5. **"中位校准(중위 캘리브레이션)"** 클릭 → 현재 회전축 위치를 중위(0~4095의 중앙)로 설정.
6. **"ID"** 클릭 → 우측 하단에서 해당 서보의 ID 번호를 입력하고 **"保存(저장)"**. 번호는 **문자를 붙이지 않은 순수 아라비아 숫자**여야 합니다.
7. 서보와 컨트롤 보드를 잇는 선을 뺍니다.
8. 서보에 서보 케이블을 꽂습니다.
   - **1번 서보에는 케이블 2개**, 나머지 서보는 우선 **1개만** 꽂습니다.

:::tip 중위 캘리브레이션을 잊지 마세요
ID만 설정하고 중위 캘리브레이션을 빠뜨리면, 조립 후 **한쪽 방향으로만 움직이거나 가동범위가 절반밖에 안 나오는** 문제가 생깁니다.
:::

## 방법 C — 웹 브라우저 도구 (설치 불필요)

WebSerial API를 사용하는 도구로, 크롬/엣지 계열 브라우저에서 바로 동작합니다.

- 주소: [bambot.org/feetech.js?lang=zh](https://bambot.org/feetech.js?lang=zh)

### 단계

1. 서보 모델에 따라 **0 또는 1**을 입력하고 **"연결(连接)"** 클릭.
2. **ID 1~6 범위를 스캔**합니다. 결과의 `FOUND` 표시로 어떤 ID의 서보가 응답하는지 확인합니다.
3. ID 설정과 중위 캘리브레이션:
   - ① "현재 서보 ID"에 스캔된 ID를 입력
   - ② **"ID 관리"** 에 새 숫자를 입력하고 **"ID 변경"** 클릭
   - ③ **중위 캘리브레이션**:
     - **STS3215** → "위치 제어"에 **2047** 입력 후 `Set`
     - **SCS0009** → "위치 제어"에 **511** 입력 후 `Set`

:::info 중위 값이 서보마다 다릅니다
STS 계열은 12비트(0~4095)라 중위가 **2047/2048**, SCS0009는 10비트(0~1023)라 중위가 **511**입니다. 혼동하지 마세요.
:::

## 방법 D — Juxi ServoController (크로스 플랫폼 GUI)

원문 위키가 배포하는 `Juxi_ServoController.zip` 도구입니다. Seeed Studio의 `Seeed_RoboController`(MIT)를 기반으로 GUI를 재구성하고 FT 디버거, xdat 파라미터 백업/복원, 크로스 플랫폼 지원, 중/영 전환을 추가한 버전입니다.

:::warn 호환성
**Feetech STS3215 계열 전용**입니다. 레지스터 표, xdat 파라미터 포맷, 보레이트 표 모두 STS3215에 맞춰져 있습니다.
:::

### 주요 기능

| 기능 | 설명 |
| --- | --- |
| 자동 포트 감지 | USB 시리얼을 지능적으로 인식하고 가상 장치를 자동 제외 |
| 크로스 플랫폼 | Windows / Ubuntu / macOS |
| 이중 포트 동기화 | 좌·우 두 시리얼 포트를 독립 조작, 리더-팔로워 동기 원격조작 지원 |
| 중위 캘리브레이션 | 현재 위치를 2048 중위로 EEPROM에 기록 |
| 중위 테스트 | 토크를 켜고 중위로 이동시켜 캘리브레이션 결과 검증 |
| 모터 토크 해제 (失能电机) | 전 서보 토크를 한 번에 꺼서 손으로 자유롭게 움직일 수 있게 함 |
| 자동 스캔 | ID 1~20 범위의 온라인 서보 자동 탐지 |
| FT 디버거 | 파라미터 읽기/쓰기, 위치 제어, 보레이트 변경, 공장 초기화, xdat 백업 |
| LeRobot 캘리브레이션 | LeRobot 포맷 JSON 캘리브레이션 파일 생성 |

### 설치와 실행

```bash
cd Juxi_ServoController
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
pip install -r requirements.txt
python setup.py
python -m src.gui.factory_calibration_tool
```

Linux (Ubuntu / Debian) — 한글/중문 폰트와 시리얼 권한이 필요합니다:

```bash
sudo apt install python3-venv fonts-noto-cjk fonts-noto-color-emoji
sudo usermod -a -G dialout $USER   # 로그아웃 후 재로그인해야 적용
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m src.gui.factory_calibration_tool
```

macOS — `/dev/tty.*` 대신 **논블로킹인 `/dev/cu.usbserial-*`** 를 쓰는 것이 좋습니다:

```bash
brew install python
ls /dev/cu.*
python -m src.gui.factory_calibration_tool \
  --port1 /dev/cu.usbserial-0001 --port2 /dev/cu.usbmodem141101
```

포트를 수동 지정하려면:

```bash
python -m src.gui.factory_calibration_tool --port1 COM3 --port2 COM4
```

```text

│  SoARM 시리즈 캘리브레이션 툴   [포트1▾][포트2▾][🔄][🎮][EN] │ ← 상단바
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────┬──────────────────────────────┐ │
│  │ 포트1 - 서보 캘리브레이션│ 포트2 - 서보 캘리브레이션    │ │
│  │  [🔴미연결] 현재 서보:…  │  [🔴미연결] 현재 서보:…      │ │
│  │  서보 1~6 상태 테이블    │  서보 1~6 상태 테이블        │ │
│  │  [중위 캘리브][중위 테스트]│ [중위 캘리브][중위 테스트]  │ │
│  └─────────────────────────┴──────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

- **Tab1 서보 캘리브레이션** — 좌우 패널 단축 조작(중위 캘리브레이션, 중위 테스트, 토크 해제)과 실시간 상태
- **Tab2 단일 서보 제어** — 각 온라인 서보를 슬라이더로 미세 조정, 토크 On/Off
- **Tab3 FT 디버거** — 시리얼 연결, 스캔, 파라미터 읽기/쓰기, 위치 제어, 보레이트/공장 초기화, xdat 백업 복원

### 사용 절차

**1. 연결과 서보 인식**

USB-시리얼 어댑터로 컨트롤 보드를 연결하고 서보에 전원을 공급합니다. GUI 상단바에서 포트를 선택(또는 🔄 새로고침)하면 패널 상단이 🟢 연결됨으로 바뀌고 ID 1~20 범위의 온라인 서보를 자동 스캔합니다(보통 1~6).

포트 점유 오류가 나면 **다른 프로그램(시리얼 모니터, 종료되지 않은 이전 툴)이 그 포트를 잡고 있지 않은지** 확인하세요.

**2. 중위 캘리브레이션 (현재 위치를 2048로)**

1. 캘리브레이션 **전에 물리적으로 자세를 잡아** 각 관절이 원하는 "영점/중위"에 오도록 합니다.
2. **[포트X 중위 캘리브레이션]** 버튼 클릭.
3. 프로그램이 먼저 서보를 비활성화하고, 손으로 원하는 중위까지 조정하라고 안내합니다.
4. 확인하면 각 서보에 대해 **EEPROM 잠금 해제 → 주소 40에 값 128 기록 → EEPROM 재잠금**을 수행합니다.

**3. 중위 테스트**

**[포트X 중위 테스트]** 를 누르면 토크를 켜고 모든 서보를 2048로 이동시킵니다.

- 서보가 **거의 움직이지 않으면** → 캘리브레이션 성공
- **크게 움직이면** → 캘리브레이션 값이 잘못된 것이므로 재수행

**4. 모터 토크 해제 (수동 조정)**

**[포트X 모터 비활성화]** 로 해당 포트의 전 서보 토크를 끄면 자유롭게 손으로 돌릴 수 있습니다. 개별 서보는 "단일 서보 제어" 탭의 슬라이더 아래 토크 스위치로 따로 제어합니다.

**5. 서보 ID 변경**

1. **🔬 FT 디버거** 탭에서 시리얼 연결 후 서보를 스캔합니다.
2. 대상 서보를 선택하고 파라미터 표에서 **"서보 ID"(주소 0x05)** 값을 수정한 뒤 쓰기.
3. 프로그램이 **잠금 해제 → 주소 5 기록 → 새 ID 검증 → 재잠금**을 수행합니다.

:::warn ID 변경 시
**버스에 해당 서보 하나만** 연결되어 있어야 ID 충돌을 피할 수 있습니다.
:::

**6. 보레이트 변경 / 공장 초기화**

- **보레이트 변경**: FT 디버거의 "보레이트 / 공장 초기화" 영역에서 새 보레이트(38400 ~ 1000000 bps)를 선택합니다. 기록 후 자동으로 시리얼 보레이트를 전환해 ping 검증하며, 실패하면 자동 롤백합니다.
- **공장 초기화**: 서보가 출하 기본값(**ID=1, 보레이트=1000000**)으로 돌아갑니다. 이후 다시 스캔해야 합니다.

**7. xdat 파라미터 백업과 복원**

- **💾 현재 서보 저장** — 선택된 서보의 EEPROM 파라미터를 xdat 파일로 백업
- **📂 xdat 열기** — 백업 파일 로드
- **📤 서보로 복원** — 백업을 현재 서보에 다시 기록

:::tip 처음 설정을 마치면 바로 백업하세요
ID·보레이트·중위가 모두 잡힌 직후 6개 서보의 xdat를 백업해 두면, 나중에 실수로 파라미터를 날려도 몇 초 만에 복구할 수 있습니다.
:::
