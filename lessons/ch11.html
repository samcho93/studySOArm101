PART 3 텔레오퍼레이션과 데이터 수집 · 약 40분

11실기 데이터셋 수집

lerobot-record로 에피소드를 녹화하고, 좋은 데이터셋이 갖춰야 할 조건을 배웁니다.

시뮬레이터 열기 URDF 뷰어 명령어 생성기

무엇을 기록하는가#

lerobot-record는 텔레오퍼레이션을 하면서 매 프레임 다음을 저장합니다.

컬럼내용출처
action리더 암의 관절 값 6개teleoperator
observation.state팔로워 암의 실제 관절 값 6개robot
observation.images.<name>각 카메라 프레임cameras
task작업 설명 텍스트--dataset.single_task
timestamp, frame_index, episode_index메타데이터자동

이 구조가 LeRobotDataset 포맷입니다. 정책은 observation을 보고 action을 예측하도록 학습됩니다.

기본 녹화 명령#

bash
lerobot-record \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_awesome_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 1920, height: 1080, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_awesome_leader_arm \
    --display_data=true \
    --dataset.repo_id=${HF_USER}/record-test \
    --dataset.num_episodes=5 \
    --dataset.single_task="Grab the black cube" \
    --dataset.streaming_encoding=true \
    --dataset.encoder_threads=2
명령어 생성기

명령어 생성기의 "녹화" 탭에서 포트·카메라·에피소드 수를 입력하면 위 명령을 바로 만들어 줍니다.

로컬에만 저장하기 (Hub 업로드 없이)#

기본값은 녹화가 끝나면 Hugging Face Hub에 업로드합니다. 로컬에만 두려면:

bash
lerobot-record \
    ... \
    --dataset.repo_id=myname/so101_pick_cube \
    --dataset.root=./datasets/so101_pick_cube \
    --dataset.push_to_hub=false \
    --dataset.no_stamp=true \
    --dataset.single_task="Pick the cube and place it in the bin" \
    --dataset.num_episodes=50 \
    --dataset.fps=30 \
    --dataset.episode_time_s=30 \
    --dataset.reset_time_s=10 \
    --dataset.video=true
`--dataset.no_stamp=true` 를 꼭 넣으세요

이 옵션이 없으면 repo_id에 타임스탬프가 자동으로 붙습니다. 그러면 나중에 이어 녹화(resume)·재생(replay)·학습(train)할 때 데이터셋을 찾지 못합니다. 원문 위키의 듀얼암 튜토리얼도 이 점을 강하게 경고합니다.

repo_id에 `/` 를 넣으세요

로컬 전용이라도 사용자명/데이터셋명 형태를 쓰는 것이 좋습니다. 나중에 Hub에 올릴 때 그대로 쓸 수 있습니다.

Hub에 업로드하기#

bash
hf auth login --token ${HUGGINGFACE_TOKEN} --add-to-git-credential
HF_USER=$(NO_COLOR=1 hf auth whoami | awk -F': *' 'NR==1 {print $2}')
echo $HF_USER

--dataset.root와 --dataset.push_to_hub=false를 빼면 자동 업로드됩니다.

bash
--dataset.repo_id=${HF_USER}/so101_pick_cube

로컬 복사본은 ~/.cache/huggingface/lerobot/{repo_id}/에 남습니다.

수동 업로드:

bash
hf upload ${HF_USER}/so101_pick_cube ~/.cache/huggingface/lerobot/${HF_USER}/so101_pick_cube --repo-type dataset

업로드한 데이터셋은 온라인 뷰어에서 repo_id를 붙여 넣어 바로 확인할 수 있습니다. 업로드 시 LeRobot 태그가 자동으로 붙습니다.

녹화 중 키보드 조작#

키동작
→ 또는 **n**현재 에피소드(또는 리셋 시간)를 조기 종료하고 다음으로
← 또는 **r**현재 에피소드를 취소하고 다시 녹화
ESC 또는 **q**세션 즉시 종료 → 영상 인코딩 후 업로드
헤드리스/SSH에서도 동작합니다

이 제어 키들은 전역 키보드 백엔드가 없어도 터미널에서 직접 읽습니다. X11·Wayland·헤드리스·SSH 모두 동작하며, $DISPLAY 설정이 필요 없습니다. 단, 대화형 터미널(TTY)에서 실행하고 창이 포커스되어 있어야 합니다.

녹화 파라미터#

옵션기본값설명
--dataset.num_episodes50녹화할 에피소드 수
--dataset.episode_time_s60에피소드 1개의 최대 길이(초)
--dataset.reset_time_s60에피소드 사이 환경 리셋 시간(초)
--dataset.fps30샘플링 주파수
--dataset.videotrue영상으로 인코딩(용량 절약)
--dataset.push_to_hubtrueHub 업로드 여부
--dataset.no_stampfalserepo_id에 타임스탬프 붙이지 않음
--resumefalse기존 데이터셋에 이어 녹화
시간 설정 감각

"큐브를 집어 상자에 넣기" 정도의 작업은 에피소드 15~30초, 리셋 5~10초면 충분합니다. 기본값 60초는 너무 길어 지루하고 디스크만 먹습니다.

이어 녹화 (resume)#

중간에 종료했거나 여러 번에 나눠 모을 때 사용합니다.

bash
lerobot-record \
    ... \
    --dataset.repo_id=myname/so101_pick_cube \
    --dataset.root=./datasets/so101_pick_cube \
    --resume=true \
    --dataset.num_episodes=35
resume의 3가지 함정
  1. **--resume=true가 없으면** LeRobotDataset.create()가 "디렉터리가 이미 존재한다"며 에러를 냅니다.
  2. **--dataset.root와 --dataset.repo_id가 첫 녹화와 완전히 같아야** 합니다. resume은 root를 명시적으로 요구합니다.
  3. **--dataset.num_episodes는 "이번에 추가로 녹화할 개수" 입니다. 총 목표치가 아닙니다. 이미 15개를 찍었고 50개를 채우고 싶다면 35**를 쓰세요.
종료 타이밍

에피소드 녹화 중이거나 자연 종료된 직후에 나가세요. "Reset the environment" 단계에서 나가면 프레임이 없는 빈 에피소드가 저장에 실패합니다. (You must add one or several frames before calling add_episode 오류) 이미 녹화된 데이터에는 영향이 없으니 --resume=true로 계속하면 됩니다.

재생과 편집#

특정 에피소드 재생#

bash
lerobot-replay \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_awesome_follower_arm \
    --dataset.repo_id=myname/so101_pick_cube \
    --dataset.root=./datasets/so101_pick_cube \
    --dataset.episode=24
인덱스는 0부터

--dataset.episode=24는 25번째 에피소드입니다.

재생은 로봇의 반복성 검증과 같은 모델 간 전이 가능성 확인에 유용합니다. 녹화 때와 다른 궤적으로 움직인다면 캘리브레이션이나 기구 유격을 의심하세요.

에피소드 삭제#

잘못 녹화한 에피소드를 지울 수 있습니다.

bash
python -m lerobot.scripts.lerobot_edit_dataset \
    --repo_id=myname/so101_pick_cube \
    --root=./datasets/so101_pick_cube \
    --operation.type=delete_episodes \
    --operation.episode_indices="[24]"

삭제하면 데이터셋이 제자리에서 다시 쓰이고, 원본은 ./datasets/so101_pick_cube_old/에 백업됩니다. 새 데이터셋이 정상인지 확인한 뒤 백업을 지우세요.

bash
rm -rf ./datasets/so101_pick_cube_old

전체 삭제:

bash
rm -rf ./datasets/so101_pick_cube

데이터셋 디렉터리 구조#

text
datasets/so101_pick_cube/

│   ├── info.json          # fps, 특징 shape 등 데이터셋 정보

좋은 데이터셋 만들기#

권장 수집 전략
  1. 처음에는 단순하게. "물체를 집어 상자에 넣기" 하나만. 색·모양·위치를 고정합니다.
  2. 최소 50개 에피소드. 물체 위치를 5곳으로 나누고 위치당 10개씩 찍습니다.
  3. 카메라는 절대 고정. 수집 중 절대 건드리지 마세요.
  4. 파지 방식을 일관되게. 매번 같은 방향, 같은 접근 경로로 잡습니다.
  5. 물체가 항상 카메라에 보이게. 팔에 가려지는 구간이 길면 정책이 배우지 못합니다.
  6. 변화는 나중에 조금씩. 안정적인 성공률을 확보한 뒤 파지 위치, 파지 방식, 카메라 각도 순으로 천천히 다양성을 늘립니다.
변화를 한꺼번에 주지 마세요

"이왕 하는 김에" 하고 물체 종류·위치·조명을 동시에 바꾸면, 각 조건의 샘플 수가 부족해져 어느 것도 제대로 배우지 못합니다. 변화는 성공률이 안정된 후에 하나씩 추가하세요.

수집 중 품질 체크#

확인기준
성공률사람이 조작해도 실패하는 에피소드는 r로 다시 녹화
속도일정하게. 급격한 가속은 팔로워 추종 오차를 만듦
정지 구간너무 긴 정지는 정책이 "멈춤"을 배우게 함

문제 해결#

증상원인해결
FileExistsError같은 이름 데이터셋 존재--resume=true 또는 디렉터리 삭제
resume 시 root 요구 오류root 미지정--dataset.root=... 추가 (첫 녹화와 동일)
디렉터리에 타임스탬프가 붙음no_stamp 미설정--dataset.no_stamp=true
키 입력이 안 먹힘비대화형 터미널TTY 터미널에서 실행, 창 포커스
자동 업로드가 됨기본값이 업로드--dataset.push_to_hub=false
--dataset.vcodec 파라미터 없음구버전 옵션--dataset.rgb_encoder.vcodec=h264 (기본은 libsvtav1)
영상 인코딩이 매우 느림스레드 부족--dataset.encoder_threads=4
프레임 드롭USB 대역폭 / CPU 부족해상도 낮춤, 카메라 수 줄임
