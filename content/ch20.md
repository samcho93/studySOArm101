## 왜 둘을 잇는가

두 생태계는 잘하는 것이 다릅니다.

| | LeRobot | ROS 2 |
| --- | --- | --- |
| 강점 | 모방학습, 데이터셋, VLA 정책 | 모션 플래닝, 충돌 회피, 센서 통합, 다중 로봇 |
| 통신 | DORA 데이터플로 (코드 핫 리로드) | DDS 기반 pub/sub, 산업 표준 |
| 시뮬레이션 | gym 환경, Isaac Lab | Gazebo, MoveIt |
| 생태계 | AI/ML 중심 | 로보틱스 전반 |

**학습한 정책으로 물체를 집되, 이동 경로는 MoveIt이 충돌 없이 계획**하게 하고 싶다면 둘을 이어야 합니다.

:::info 원문 위키의 언급
LeRobot 생태계의 DORA 분산 데이터플로 엔진은 코드 핫 리로드로 재시작 없이 정책을 조정할 수 있습니다. 원문 위키는 여기에 더해 "파이썬 실행 성능이 ROS 2보다 17배 빠르다"고 소개하지만, **제조사 측 주장이고 측정 조건이 공개되어 있지 않으므로** 설계 근거로 삼지는 마세요. 반대로 표준 모션 플래닝과 도구 생태계는 ROS 2가 압도적입니다. 둘은 대체재가 아니라 보완재입니다.
:::

## 세 가지 통합 방식

@fig[bridge-modes] 세 가지 통합 방식. 무엇을 포기하고 무엇을 얻는지가 다릅니다.

### 방식 1 — 정책을 ROS 2 노드로 감싸기 (권장)

```text
카메라 토픽 ──┐
              ├─→ [정책 노드] ─→ /joint_trajectory_controller/joint_trajectory
/joint_states ┘        ↑
                  LeRobot 정책 (PyTorch)
```

- **장점**: ROS 2의 컨트롤러·안전장치·시각화를 모두 활용
- **단점**: 추론 지연이 제어 주기에 직접 영향

### 방식 2 — LeRobot이 주도하고 ROS 2는 관측만

```text
LeRobot (시리얼 직접 제어) ─→ 서보
        └─→ [상태 발행 노드] ─→ /joint_states (RViz·기록용)
```

- **장점**: LeRobot의 성능과 동작을 그대로 유지
- **단점**: MoveIt 충돌 회피를 쓸 수 없음

### 방식 3 — 작업 단계별로 번갈아 쓰기

```text
[접근] MoveIt으로 물체 위 10cm까지 충돌 없이 이동
   ↓  (하드웨어 제어권 인계)
[파지] LeRobot 정책으로 세밀한 파지 수행
   ↓
[운반] MoveIt으로 목표 지점까지
```

- **장점**: 각자의 강점만 사용
- **단점**: 제어권 전환 로직이 필요

:::warn 시리얼 포트는 하나입니다
방식 2·3에서 **LeRobot과 ROS 2 하드웨어 인터페이스가 동시에 같은 시리얼 포트를 열 수 없습니다.** 반드시 한쪽이 포트를 닫은 뒤 다른 쪽이 열어야 합니다.
:::

## 구현 1 — 정책 노드

`scripts/lerobot_ros2_bridge.py`의 핵심 구조입니다.

```python
#!/usr/bin/env python3
"""LeRobot 정책을 ROS 2 노드로 감싸는 브릿지."""

import numpy as np
import rclpy
import torch
from cv_bridge import CvBridge
from rclpy.node import Node
from sensor_msgs.msg import Image, JointState
from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint

from lerobot.policies.act.modeling_act import ACTPolicy

JOINTS = ["shoulder_pan", "shoulder_lift", "elbow_flex",
          "wrist_flex", "wrist_roll", "gripper"]


class LeRobotPolicyNode(Node):
    def __init__(self):
        super().__init__("lerobot_policy_node")

        self.declare_parameter("policy_path", "outputs/train/act_so101/checkpoints/last/pretrained_model")
        self.declare_parameter("rate_hz", 30.0)
        self.declare_parameter("task", "Grab the black cube")

        path = self.get_parameter("policy_path").value
        self.task = self.get_parameter("task").value
        rate = self.get_parameter("rate_hz").value

        self.get_logger().info(f"정책 로드: {path}")
        self.device = "cuda" if torch.cuda.is_available() else "cpu"
        self.policy = ACTPolicy.from_pretrained(path).to(self.device).eval()

        self.bridge = CvBridge()
        self.latest_state = None
        self.latest_images = {}

        self.create_subscription(JointState, "/joint_states", self.on_state, 10)
        self.create_subscription(Image, "/camera/front/image_raw",
                                 lambda m: self.on_image("front", m), 10)
        self.create_subscription(Image, "/camera/wrist/image_raw",
                                 lambda m: self.on_image("wrist", m), 10)

        self.pub = self.create_publisher(
            JointTrajectory, "/joint_trajectory_controller/joint_trajectory", 10)

        self.create_timer(1.0 / rate, self.step)
        self.get_logger().info("브릿지 준비 완료")

    # ---- 구독 콜백 --------------------------------------------------
    def on_state(self, msg: JointState):
        # /joint_states 의 순서는 보장되지 않으므로 이름으로 매핑한다
        index = {name: i for i, name in enumerate(msg.name)}
        try:
            self.latest_state = np.array(
                [msg.position[index[j]] for j in JOINTS], dtype=np.float32)
        except KeyError:
            pass   # 아직 모든 조인트가 발행되지 않음

    def on_image(self, key: str, msg: Image):
        self.latest_images[key] = self.bridge.imgmsg_to_cv2(msg, "rgb8")

    # ---- 제어 루프 --------------------------------------------------
    def step(self):
        if self.latest_state is None or len(self.latest_images) < 1:
            return

        observation = {
            "observation.state": torch.from_numpy(self.latest_state)
                                      .unsqueeze(0).to(self.device),
            "task": [self.task],
        }
        for key, image in self.latest_images.items():
            tensor = torch.from_numpy(image).permute(2, 0, 1).float() / 255.0
            observation[f"observation.images.{key}"] = tensor.unsqueeze(0).to(self.device)

        with torch.inference_mode():
            action = self.policy.select_action(observation)

        self.publish(action.squeeze(0).cpu().numpy())

    def publish(self, positions: np.ndarray):
        traj = JointTrajectory()
        traj.joint_names = JOINTS
        point = JointTrajectoryPoint()
        point.positions = [float(v) for v in positions]
        point.time_from_start.sec = 0
        point.time_from_start.nanosec = 50_000_000   # 50 ms
        traj.points = [point]
        self.pub.publish(traj)


def main():
    rclpy.init()
    node = LeRobotPolicyNode()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.shutdown()


if __name__ == "__main__":
    main()
```

실행:

```bash
ros2 run so_arm_utils lerobot_policy_node \
  --ros-args \
  -p policy_path:=outputs/train/act_so101_pick/checkpoints/last/pretrained_model \
  -p task:="Grab the black cube" \
  -p rate_hz:=30.0
```

:::danger 단위를 반드시 확인하세요
LeRobot 정책의 출력은 **캘리브레이션 기반 정규화 값(-100~100, 그리퍼 0~100)** 일 수 있고, ROS 2 `JointTrajectory`는 **라디안**을 기대합니다.

정책 설정의 `output_features`와 데이터셋의 `stats.json`을 확인해 **정규화 해제(unnormalize)** 가 어디서 이뤄지는지 파악하세요. 잘못하면 팔이 한계까지 급격히 튑니다. 첫 실행은 **반드시 Mock 모드나 Gazebo에서** 하세요.
:::

## 구현 3 — 제어권 전환 (방식 3)

MoveIt과 정책이 번갈아 팔을 제어하게 만드는 상태 머신입니다.

```python
class PickPlaceOrchestrator(Node):
    """MoveIt(이동) + LeRobot 정책(파지) 하이브리드."""

    def run(self):
        # 1) MoveIt: 홈 → pre-grasp (충돌 회피)
        self.moveit_goto_named("rest")
        self.moveit_goto_pose(x=0.22, y=0.0, z=0.15)

        # 2) 정책 노드 활성화 → 파지 수행
        self.set_policy_active(True)
        self.wait_until_grasped(timeout=15.0)
        self.set_policy_active(False)

        # 3) MoveIt: 직선 상승 후 목표 지점으로
        self.moveit_cartesian_relative(dz=+0.10)
        self.moveit_goto_pose(x=0.10, y=0.20, z=0.18)

        # 4) 그리퍼 열기
        self.command_gripper(open_=True)

        # 5) 홈 복귀
        self.moveit_goto_named("rest")
```

:::tip 전환 시 주의
정책 노드와 MoveIt이 **동시에 같은 컨트롤러에 명령을 쓰면** 궤적이 충돌합니다. 한쪽이 명령을 멈춘 것을 확인한 뒤 다른 쪽을 시작하세요. `set_policy_active(False)` 후 최소 한 제어 주기는 기다리는 것이 안전합니다.
:::

## 데이터 흐름 검증

브릿지가 제대로 동작하는지 단계별로 확인합니다.

```bash
# 1) 카메라 토픽이 나오는가
ros2 topic hz /camera/front/image_raw

# 2) 관절 상태가 나오는가
ros2 topic echo /joint_states --once

# 3) 정책이 명령을 내는가
ros2 topic hz /joint_trajectory_controller/joint_trajectory

# 4) 명령 값이 상식적인가 (한계 범위 안?)
ros2 topic echo /joint_trajectory_controller/joint_trajectory --once

# 5) 전체 노드 그래프
rqt_graph
```

:::task 실습 — Mock에서 안전하게 검증
1. `controllers_bringup.launch.py`를 **mock 모드**로 실행합니다.
2. 브릿지 노드를 실행합니다.
3. RViz2에서 팔이 정책 출력대로 움직이는지 봅니다.
4. PlotJuggler로 명령 값이 조인트 한계 안에 있는지 확인합니다.

여기서 이상이 없으면 Gazebo로, 그다음 실기로 올라가세요.
:::

## 반대 방향 — ROS 2 데이터를 LeRobot 데이터셋으로

ROS 2 bag으로 수집한 데이터를 LeRobot 포맷으로 바꿀 수도 있습니다.

```bash
# 텔레오퍼레이션을 하면서 bag 기록
ros2 bag record /joint_states /camera/front/image_raw /camera/wrist/image_raw

# 변환
python scripts/rosbag_to_lerobot.py \
  --bag ./rosbag2_2026_09_21-14_30_00 \
  --repo-id myname/so101_from_rosbag \
  --root ./datasets/so101_from_rosbag \
  --fps 30
```

:::tip 이 경로가 유용한 경우
이미 ROS 2 기반 시스템(예: Gazebo, 다른 로봇)에서 시연 데이터를 모으고 있다면, 이를 LeRobot 포맷으로 바꿔 **ACT나 SmolVLA 학습**에 바로 쓸 수 있습니다.
:::

## 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 정책이 아무 명령도 안 냄 | 관측 미수신 | `ros2 topic hz`로 각 입력 확인 |
| 팔이 한계까지 튐 | 단위/정규화 불일치 | `stats.json` 확인, Mock에서 먼저 검증 |
| 동작이 끊김 | 추론이 제어 주기보다 느림 | `rate_hz` 낮춤, RTC 추론 사용 |
| `/joint_states` 순서가 다름 | 발행 순서 미보장 | **이름으로 매핑** (위 코드 참고) |
| 시리얼 포트 충돌 | LeRobot과 ROS 2 동시 실행 | 한쪽만 실행 |
| 영상 지연이 큼 | 압축 미사용 | `image_transport` compressed 사용 |
| GPU 메모리 부족 | 정책 + 다른 프로세스 | 다른 GPU 작업 종료 |
