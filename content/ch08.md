## 왜 캘리브레이션이 중요한가

> 캘리브레이션 과정은 매우 중요합니다. **한 로봇에서 학습한 신경망이 다른 로봇에서도 동작하게 만드는 것이 바로 캘리브레이션**이기 때문입니다.
> — LeRobot 공식 문서

생각해 봅시다. 여러분이 만든 팔로워 암과 제가 만든 팔로워 암은 3D 프린팅 오차, 서보 혼을 끼운 각도, 조립 시 조인 위치가 전부 조금씩 다릅니다. 같은 "어깨 30°"라도 실제 물리 자세는 다릅니다.

캘리브레이션은 **각 관절의 물리적 가동범위를 측정해서, 소프트웨어 숫자와 실제 각도를 일치시키는 작업**입니다. 이것이 맞아야:

1. **리더를 움직이면 팔로워가 똑같은 자세**가 됩니다. (텔레오퍼레이션)
2. 다른 사람이 만든 데이터셋으로 학습한 모델이 **내 로봇에서도 동작**합니다. (정책 전이)
3. ROS 2 / RViz에 표시되는 모델이 **실제 팔과 같은 자세**로 보입니다.

:::danger 캘리브레이션을 건너뛰면
텔레오퍼레이션 시 팔로워가 **엉뚱한 자세로 급격히 움직여** 부품이 부러지거나 서보가 과부하로 타버릴 수 있습니다. 반드시 먼저 수행하세요.
:::

---

## 두 단계의 캘리브레이션

혼동하기 쉬운데, SO-ARM101에는 **성격이 다른 두 가지 캘리브레이션**이 있습니다.

| 구분 | 서보 중위 캘리브레이션 | LeRobot 캘리브레이션 |
| --- | --- | --- |
| 대상 | 서보 EEPROM | LeRobot 설정 파일 (JSON) |
| 시점 | **조립 전** | **조립 후** |
| 내용 | 현재 위치를 2048로 기록 | 각 관절의 최소·최대 범위 측정 |
| 도구 | FD 툴 / 웹 도구 / Juxi 툴 | `lerobot-calibrate` |
| 다룬 장 | [5장](~/lessons/ch05.html) | **이 장** |

@fig[calibration-stages] 이름이 비슷해 헷갈리지만 **대상도 시점도 다릅니다.**

이 장은 두 번째, **LeRobot 캘리브레이션**입니다.

## 팔로워 암 캘리브레이션

```bash
lerobot-calibrate \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_awesome_follower_arm
```

파이썬 API:

```python
from lerobot.robots.so_follower import SO101FollowerConfig, SO101Follower

config = SO101FollowerConfig(
    port="/dev/ttyACM0",
    id="my_awesome_follower_arm",
)

follower = SO101Follower(config)
follower.connect(calibrate=False)
follower.calibrate()
follower.disconnect()
```

:::warn `--robot.id` 는 나중에 계속 씁니다
이 id가 캘리브레이션 파일의 이름이 됩니다. **텔레오퍼레이션·녹화·평가에서 같은 id를 써야** 같은 캘리브레이션이 적용됩니다. 팔마다 고유하고 기억하기 쉬운 이름을 정하세요.
:::

## 캘리브레이션 절차

화면 안내를 따르면 되지만, 두 단계의 의미를 알고 하면 훨씬 정확해집니다.

### 1단계 — 중간 자세로 이동

> 먼저 모든 관절이 가동범위의 **한가운데**에 오도록 로봇을 움직이세요.

손으로 팔을 잡고, 각 관절이 대략 "양쪽으로 똑같이 갈 수 있는" 중간 위치에 오도록 배치합니다. 그 상태에서 Enter를 누르면 **영점(zero offset)** 이 기록됩니다.

:::tip 중간 자세 잡는 요령
- `shoulder_pan`: 팔이 **정면**을 향하게
- `shoulder_lift`: 상완이 **수직**에 가깝게
- `elbow_flex`: 전완이 상완과 **약 90°**
- `wrist_flex`: 손목이 **일직선**
- `wrist_roll`: 그리퍼가 **수평**
- `gripper`: **반쯤 벌어진** 상태
:::

### 2단계 — 각 관절을 전 가동범위로 움직이기

> Enter를 누른 뒤, **각 관절을 가동범위 끝에서 끝까지** 움직이세요.

한 관절씩 천천히, **끝까지** 돌렸다가 반대쪽 끝까지 돌립니다. LeRobot이 그동안 측정된 최솟값과 최댓값을 기록합니다.

:::danger 힘으로 밀어붙이지 마세요
저항이 느껴지면 그 지점이 물리적 한계입니다. **더 밀면 3D 프린팅 부품이 깨지거나 기어가 마모됩니다.** 부드럽게 멈추는 지점까지만 움직이세요.
:::

:::warn 빠뜨리기 쉬운 것
**모든 6개 관절**(그리퍼 포함)을 움직여야 합니다. 하나라도 빠뜨리면 그 관절의 범위가 0으로 기록되어 나중에 전혀 움직이지 않습니다.
:::

완료하면 Enter를 눌러 종료합니다.

## 리더 암 캘리브레이션

동일한 과정을 `teleop` 타입으로 반복합니다.

```bash
lerobot-calibrate \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_awesome_leader_arm
```

```python
from lerobot.teleoperators.so_leader import SO101LeaderConfig, SO101Leader

config = SO101LeaderConfig(
    port="/dev/ttyACM1",
    id="my_awesome_leader_arm",
)

leader = SO101Leader(config)
leader.connect(calibrate=False)
leader.calibrate()
leader.disconnect()
```

:::info 리더는 훨씬 쉽습니다
리더 암은 감속비가 낮아 손으로 가볍게 움직입니다. 대신 **자체 무게로 처질 수 있으니** 한 손으로 받치면서 진행하세요.
:::

## 캘리브레이션 파일 위치

결과는 사용자 캐시에 JSON으로 저장됩니다.

```text
~/.cache/huggingface/lerobot/calibration/
├── robots/
│   └── so_follower/
│       └── my_awesome_follower_arm.json
└── teleoperators/
    └── so_leader/
        └── my_awesome_leader_arm.json
```

:::info 디렉터리 이름이 `so_follower` / `so_leader` 인 이유
LeRobot 내부에서 `so101_follower`와 `so100_follower`가 **같은 구현을 공유**하기 때문에 디렉터리가 통합되어 있습니다. 마찬가지로 `so101_leader`와 `so100_leader`도 `so_leader` 하나를 씁니다.

또한 **리더는 로봇이 아니라 teleoperator**이므로 `robots/`가 아니라 `teleoperators/` 아래에 저장됩니다. 파일을 직접 찾을 때 헷갈리는 지점입니다.
:::

### 파일 내용 예시

```json
{
  "shoulder_pan":  { "id": 1, "drive_mode": 0, "homing_offset": -13, "range_min": 742,  "range_max": 3339 },
  "shoulder_lift": { "id": 2, "drive_mode": 0, "homing_offset": 1024, "range_min": 810, "range_max": 3290 },
  "elbow_flex":    { "id": 3, "drive_mode": 0, "homing_offset": -1024, "range_min": 900, "range_max": 3190 },
  "wrist_flex":    { "id": 4, "drive_mode": 0, "homing_offset": 45,   "range_min": 880,  "range_max": 3210 },
  "wrist_roll":    { "id": 5, "drive_mode": 0, "homing_offset": -8,   "range_min": 200,  "range_max": 3900 },
  "gripper":       { "id": 6, "drive_mode": 0, "homing_offset": 100,  "range_min": 2020, "range_max": 3200 }
}
```

- `range_min` / `range_max` — 측정된 서보 틱 범위 (0~4095)
- `homing_offset` — 영점 보정값
- LeRobot은 이 범위를 **-100 ~ +100** (그리퍼는 **0 ~ 100**) 으로 정규화해 사용합니다.

:::tip 백업하세요
이 JSON들을 프로젝트 폴더에 복사해 두면, OS를 재설치하거나 다른 PC에서 작업할 때 캘리브레이션을 다시 하지 않아도 됩니다.

```bash
mkdir -p backup/calibration
cp -r ~/.cache/huggingface/lerobot/calibration/* backup/calibration/
```
:::

## 캘리브레이션 결과 확인

### 방법 1 — 자동 확인

다음 장의 텔레오퍼레이션을 실행하면 LeRobot이 자동으로 캘리브레이션 유무를 확인하고, 없으면 캘리브레이션 절차를 시작합니다.

### 방법 2 — 시뮬레이터로 비교

[3D 시뮬레이터](~/sim/index.html)에서 같은 자세를 만들어 보고 실물과 비교하세요. **"LeRobot 정규화" 단위 모드**로 전환하면 LeRobot이 출력하는 값과 직접 비교할 수 있습니다.

### 방법 3 — 범위 점검

```bash
python scripts/check_calibration.py --id my_awesome_follower_arm --role follower
```

각 관절의 측정 범위가 상식적인지 검사합니다. 범위가 지나치게 좁으면(예: 500틱 미만) 그 관절을 끝까지 움직이지 않은 것입니다.

## 더 정확한 방법 — WebUI 3점 캘리브레이션

지금까지의 절차는 **손으로 관절을 전 범위로 흔드는** 방식입니다. 간단하지만 약점이 있습니다. TheRobotStudio 저장소는 이 방식의 오차를 **관절당 ±50~200틱**으로 보고 있습니다. 4096틱이 한 바퀴이니 최악의 경우 **약 17°** 가 어긋난다는 뜻입니다.

특히 **3번 모터(`elbow_flex`)** 가 문제가 됩니다. 손으로 흔들다 보면 기계적 한계(하드스톱)까지 밀어붙이게 되고, 그 값(대략 3660틱 부근)이 그대로 최대값으로 기록됩니다. 그러면 나중에 정책이 그 근처를 명령할 때마다 **팔이 하드스톱에 부딪힙니다.**

**3-Point Calibration Studio**는 관절마다 **최소 → 홈 → 최대** 세 지점을 따로 잡아 이 문제를 줄입니다.

### 실행

```bash
lerobot-calibrate --robot.type=so101_follower --webui
```

저장소에 포함된 스크립트를 직접 실행해도 됩니다.

```bash
python pi_servo_studio.py
```

둘 다 로컬 웹 서버를 띄우며, 브라우저에서 `http://localhost:8086` 으로 접속합니다.

### 무엇이 다른가

| | 손으로 흔드는 방식 | 3점 WebUI |
| --- | --- | --- |
| 캡처 지점 | 흔드는 동안의 최소·최대 | **Min / Home / Max 를 하나씩 확정** |
| 관절 처리 | 여섯 개를 한꺼번에 | **한 번에 한 서보만** 토크를 켜서 분리 |
| 토크 | 꺼짐 (손으로 움직임) | **30%로 제한** (레지스터 48 = 300) |
| 이동 | 사람 손 속도 | **50Hz 코사인 S-커브** 보간 |
| 기대 오차 | ±50~200틱 | 그보다 작음 |
| 기존 기록 | 덮어씀 | `follower.json` 을 **이력을 지우지 않고 갱신** |

한 서보만 토크를 거는 이유는 단순합니다. 나머지 다섯 개가 힘이 빠져 있으면 **팔이 흔들려 기준점이 흐려지기** 때문입니다. 토크를 30%로 묶는 것도 같은 맥락으로, 잘못 눌렀을 때 하드스톱을 때리지 않게 하는 안전장치입니다.

:::tip 언제 이걸 쓰나
- 텔레오퍼레이션에서 **리더와 팔로워의 자세가 미묘하게 계속 어긋날 때**
- `elbow_flex` 가 특정 각도에서 **갈리는 소리**를 낼 때
- 학습한 정책의 **성공률이 시뮬레이션보다 눈에 띄게 낮을 때**

처음 조립했다면 앞의 기본 절차로 시작해도 충분합니다. 위 증상이 보이기 시작하면 그때 3점 방식으로 다시 잡으세요.
:::

:::info 문서 위치
[SO-ARM100 저장소의 `Software/WEBUI_CALIBRATION.md`](https://github.com/TheRobotStudio/SO-ARM100/blob/main/Software/WEBUI_CALIBRATION.md) 에 화면별 절차가 정리되어 있습니다.
:::

## 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 텔레오퍼레이션 중 "다시 캘리브레이션하라" 안내 | id가 다르거나 파일이 없음 | 같은 `--robot.id` / `--teleop.id` 사용 |
| 특정 관절만 안 움직임 | 그 관절을 전 범위로 움직이지 않음 | 재캘리브레이션 |
| 리더와 팔로워 자세가 어긋남 | 한쪽만 캘리브레이션함 | 양쪽 모두 수행 |
| 리더가 손으로 안 움직임 | 토크가 꺼지지 않음 | 재캘리브레이션, 또는 서보 상태 점검 |
| 가동범위가 한쪽으로 치우침 | 중위 캘리브레이션(5장) 누락 | 분해 후 5장 재수행 |
| `elbow_flex`가 끝에서 갈리는 소리 | 하드스톱 값이 최대값으로 기록됨 | **3점 WebUI 캘리브레이션**(위) |
| 캘리브레이션 중 서보 통신 끊김 | 3핀 케이블 접촉 불량 | 배선 재점검 |

[9장 텔레오퍼레이션 기초](~/lessons/ch09.html) — 드디어 리더로 팔로워를 조종합니다. 먼저 시뮬레이터에서 감을 잡고 시작합니다.
:::
