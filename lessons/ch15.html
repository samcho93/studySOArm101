15URDF와 로봇 모델 이해

so101_new_calib.urdf를 한 줄씩 해부하고, 조인트 한계표와 좌표 변환 체인을 직접 계산합니다.

시뮬레이터 열기 명령어 생성기

URDF란#

URDF(Unified Robot Description Format) 는 로봇의 구조를 기술하는 XML 파일입니다. ROS 2의 거의 모든 도구(RViz2, MoveIt 2, Gazebo, ros2_control)가 이 파일 하나를 읽고 동작합니다.

URDF가 담는 정보:

요소내용
<link>강체 부품. 시각 형상(visual), 충돌 형상(collision), 관성(inertial)
<joint>링크 사이 관절. 종류, 축, 원점, 한계
<material>색상·텍스처

SO-ARM101의 URDF 구하기#

세 가지 경로가 있습니다.

출처파일특징
TheRobotStudio/SO-ARM100Simulation/SO101/so101_new_calib.urdf공식 CAD에서 생성. 이 강좌의 기준
LeRobot 저장소내부 자산LeRobot 시각화용
URDF Studiourdf.d-robotics.cc브라우저에서 URDF를 편집·확인

이 강좌의 저장소에는 원본이 이미 포함되어 있습니다.

text
ros2_ws/src/so_arm101_description/urdf/so101_new_calib.urdf

파일 머리에는 생성 도구가 명시되어 있습니다.

xml
<?xml version="1.0" encoding="utf-8"?>
<!-- Generated using onshape-to-robot -->
<!-- Onshape https://cad.onshape.com/documents/7715cc284bb430fe6dab4ffd/... -->
<robot name="so101_new_calib">
onshape-to-robot

Onshape CAD 모델에서 URDF를 자동 생성하는 도구입니다. 그래서 원점 값들이 -8.97657e-09 처럼 지저분한 부동소수점으로 나옵니다. 사실상 0인 값들입니다.

링크 구조#

text
base_link
 └─ shoulder_link
     └─ upper_arm_link
         └─ lower_arm_link
             └─ wrist_link
                 └─ gripper_link
                     ├─ moving_jaw_so101_v1_link
                     └─ gripper_frame_link   (fixed, TCP)

각 링크는 세 가지 형상을 가집니다.

xml
<link name="upper_arm_link">
  <inertial>
    <origin xyz="-0.0898471 -0.00838224 0.0184089" rpy="0 0 0"/>
    <mass value="0.1"/>
    <inertia ixx="..." .../>
  </inertial>
  <visual>
    <origin xyz="-0.11257 -0.0155 0.0187" rpy="-3.14159 0 -1.5708"/>
    <geometry><mesh filename="package://so_arm101_description/meshes/upper_arm.stl"/></geometry>
    <material name="3d_printed"/>
  </visual>
  <collision>
    <origin xyz="-0.11257 -0.0155 0.0187" rpy="-3.14159 0 -1.5708"/>
    <geometry><mesh filename="package://so_arm101_description/meshes/upper_arm.stl"/></geometry>
  </collision>
</link>
요소용도주의
visualRViz·Gazebo에 그려지는 모습정밀한 메시 OK
collision충돌 검사단순할수록 좋음. 메시가 복잡하면 플래닝이 느려짐
inertial물리 시뮬레이션Gazebo에서 필수. 값이 이상하면 로봇이 날아감
충돌 형상 최적화

MoveIt 2 플래닝이 느리다면 collision 지오메트리를 STL 대신 박스/실린더 프리미티브로 바꾸는 것이 가장 효과적입니다. 이 강좌의 so_arm101_description 패키지는 프리미티브 버전을 xacro 옵션으로 제공합니다.

xacro로 확장하기#

URDF는 매크로가 없어 반복이 많습니다. ROS 2에서는 xacro(XML Macro)로 감싸 쓰는 것이 표준입니다.

xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="so_arm101">

  <xacro:arg name="hardware_type" default="mock"/>
  <xacro:arg name="usb_port"      default="/dev/ttyACM0"/>

  <!-- 순수 기구 구조 -->
  <xacro:include filename="$(find so_arm101_description)/urdf/so101_macro.xacro"/>
  <xacro:so101_arm prefix=""/>

  <!-- ros2_control 하드웨어 인터페이스 -->
  <xacro:include filename="$(find so_arm101_description)/urdf/so101.ros2_control.xacro"/>
  <xacro:so101_ros2_control
      name="SOArm101System"
      hardware_type="$(arg hardware_type)"
      usb_port="$(arg usb_port)"/>

</robot>

xacro를 URDF로 펼쳐 보려면:

bash
ros2 run xacro xacro src/so_arm101_description/urdf/so_arm101.urdf.xacro > /tmp/so101.urdf
check_urdf /tmp/so101.urdf

check_urdf는 링크·조인트 트리가 올바른지 검증하고 구조를 출력합니다.

bash
urdf_to_graphiz /tmp/so101.urdf   # 트리 다이어그램 PDF 생성

TheRobotStudio 저장소의 시뮬레이션 자산#

URDF 원본이 사는 곳은 TheRobotStudio/SO-ARM100 저장소의 Simulation/ 폴더입니다. 저장소 이름이 100이지만 SO-101 자산도 같은 곳에 함께 들어 있습니다.

경로내용
Simulation/SO101/so101_new_calib.urdf현재 표준. 이 강좌와 시뮬레이터가 쓰는 파일
Simulation/SO101/so101_old_calib.urdf구 캘리브레이션 규약 URDF
Simulation/SO101/so101_new_calib_camera.urdf손목 카메라 마운트가 붙은 변형 (wrist_camera_mount_link·wrist_camera_link 2개 추가)
Simulation/SO101/*.xml같은 모델의 MJCF(MuJoCo) 버전
Simulation/SO101/scene.xmlMuJoCo 씬 — 바닥·조명에 로봇을 include
Simulation/SO101/joints_properties.xml모터 파라미터 (감쇠·마찰·강성)
Simulation/SO100/so100.urdf구형 SO-100 URDF (deprecated)
Simulation/SO100/so100.rrdrerun 녹화 파일 — 받아서 바로 재생 가능

이 URDF가 만들어진 방식 — 알아 두면 좋은 네 가지#

1. onshape-to-robot으로 생성되었습니다. 원 설계는 Onshape CAD이고 URDF는 거기서 자동 변환된 결과입니다. 그래서 링크 이름과 좌표계가 사람이 손으로 쓴 URDF와는 조금 다른 냄새를 풍깁니다.

**2. 메시 경로가 package://가 아니라 상대 경로로 바뀌어 있습니다. ROS 밖(MuJoCo·rerun·PyBullet 등)에서도 그냥 열리게 하려는 의도입니다. 뒤집어 말하면 ROS 2 패키지로 감쌀 때는 이 경로를 package://so_arm101_description/meshes/... 형태로 고쳐야** 합니다. (16장에서 다룹니다.)

3. 베이스의 충돌 메시가 제거되었다고 저장소 README가 밝히고 있습니다. 시뮬레이션과 경로 계획에서 베이스 충돌 형상이 문제를 일으켰기 때문입니다.

다만 실제로 빠져 있는 쪽은 MJCF입니다. 파일을 직접 열어 확인한 결과는 이렇습니다.

파일base 링크의 충돌 형상
so101_new_calib.urdf4개 그대로 있음 (base·모터 홀더·서보·마운팅 플레이트)
so101_new_calib.xml (MJCF)0개 — 제거됨

즉 MuJoCo에서는 베이스와 팔의 충돌이 검사되지 않고, URDF를 쓰는 RViz·MoveIt·Gazebo에서는 검사됩니다. MoveIt SRDF에서 베이스 관련 쌍을 비활성화해 두는 것도 이 충돌이 실제로 존재하기 때문입니다.

4. 그리퍼는 아직 회전 조인트입니다. URDF·MJCF 모두 gripper를 라디안 단위 revolute 조인트로 기술하지만, LeRobot은 그리퍼를 0(닫힘)~100(열림)의 선형 값으로 다룹니다. 저장소도 "아직 URDF/MJCF에 반영되지 않았다"고 명시해 두었습니다. 정책 출력과 URDF 조인트 값을 직접 비교할 때 이 차이를 잊지 마세요.

new_calib과 old_calib의 차이

두 URDF는 조인트의 가상 0점을 어디에 두느냐만 다릅니다.

  • new_calib (기본) — 각 조인트의 0이 가동범위의 한가운데
  • old_calib — 각 조인트의 0이 팔을 수평으로 쭉 뻗은 자세

같은 모터 값이라도 두 URDF에서 팔 모양이 다르게 나옵니다. MuJoCo에서는 scene.xml의 include 한 줄을 바꿔 전환합니다. 이 강좌는 처음부터 끝까지 new_calib 기준입니다.

그리고 0점보다 더 성가신 차이가 하나 있습니다. 링크 이름이 통째로 다릅니다.

new_calibold_calib · SO-100 · MJCF
base_linkbase
shoulder_linkshoulder
upper_arm_linkupper_arm
lower_arm_linklower_arm
wrist_linkwrist
gripper_linkgripper
moving_jaw_so101_v1_linkjaw
gripper_frame_link (TCP)없음

old_calib에는 **TCP 프레임(gripper_frame_link) 자체가 없습니다. 이 강좌의 IK·MoveIt 설정·시뮬레이터는 모두 이 프레임을 기준으로 하므로, old_calib URDF를 그대로 끼워 넣으면 TF 조회부터 실패**합니다.

모터 파라미터의 출처

joints_properties.xml의 감쇠·마찰 값은 Open Duck Mini 프로젝트의 STS3215 파라미터를 가져와 맞춘 것입니다. 실제 서보와 완전히 같지는 않으므로, Sim2Real을 할 때는 이 값을 직접 동정(system identification)하는 편이 좋습니다.

rerun + URDF visualizer 플러그인으로 열어 보기#

ROS를 설치하지 않고 URDF를 눈으로 확인하는 가장 빠른 방법입니다. 저장소가 공식으로 안내하는 경로이기도 합니다.

설치#

bash
pip install rerun-sdk

저장소 README는 여기에 URDF visualizer 플러그인을 더 깔라고 안내합니다.

bash
pip install git+https://github.com/rerun-io/rerun-loader-python-example-urdf.git

rerun은 모르는 확장자를 만나면 외부 로더를 찾아 실행하는 구조이고, 이 플러그인이 .urdf 를 담당하는 외부 로더입니다.

최신 rerun에서는 플러그인이 필요 없습니다

rerun 0.38 기준으로 URDF 지원이 rerun 자체에 들어왔습니다. 플러그인을 PATH에서 완전히 치운 상태로 확인해 본 결과, rerun so101_new_calib.urdf 만으로 메시 17개가 그대로 올라옵니다.

버전을 확인해 보세요.

bash
rerun --version
  • 0.38 이상 — pip install rerun-sdk 만으로 충분합니다
  • 그 이하 — 플러그인을 설치해야 하고, rerun-loader-urdf 실행 파일이 PATH에 있어야 합니다. 가상환경에 깔았다면 그 환경을 활성화한 셸에서 rerun을 실행하세요
bash
which rerun-loader-urdf     # Windows: where rerun-loader-urdf

플러그인 방식에서 이 명령이 아무것도 내놓지 않으면, 뷰어는 URDF를 "모르는 파일"로 취급하고 아무것도 그리지 않습니다.

실행#

bash
git clone https://github.com/TheRobotStudio/SO-ARM100.git
cd SO-ARM100

rerun Simulation/SO101/so101_new_calib.urdf   # 현재 표준
rerun Simulation/SO101/so101_old_calib.urdf   # 구 캘리브레이션
rerun Simulation/SO100/so100.urdf             # 구형 SO-100

저장소에 들어 있는 녹화 파일도 같은 방식으로 열립니다.

bash
rerun Simulation/SO100/so100.rrd

강좌 스크립트로 움직여 보기#

뷰어로 URDF를 여는 것만으로는 자세를 바꿀 수 없습니다. 강좌에 포함된 스크립트가 이 부분을 채웁니다.

bash
cd scripts

# 기본 자세 하나
python rerun_view_so101.py --urdf ../SO-ARM100/Simulation/SO101/so101_new_calib.urdf

# 관절을 하나씩 한계까지 흔들기 — 가동범위를 눈으로 확인할 때
python rerun_view_so101.py --urdf .../so101_new_calib.urdf --sweep

# 브라우저 시뮬레이터에서 녹화한 궤적 재생
python rerun_view_so101.py --urdf .../so101_new_calib.urdf     --trajectory so101_trajectory.json

# 화면 대신 파일로 저장 (나중에 rerun sweep.rrd 로 열기)
python rerun_view_so101.py --urdf .../so101_new_calib.urdf --sweep --save sweep.rrd

스크립트는 URDF를 싣고, 이 강좌의 기구학(, 2장)으로 계산한 각 조인트 변환을 매 프레임 다시 실어 메시를 실제로 움직입니다. 함께 그려지는 것은 뼈대, TCP 점, 그리고 아래쪽 패널의 조인트·TCP 시계열 그래프입니다.

두 계산이 일치하는지 확인했습니다

rerun이 URDF에서 직접 계산한 조인트 변환을 체인으로 이어 TCP를 구한 값과, 이 강좌의 so101_kinematics.py 가 구한 TCP 값을 6개 기본 자세에서 대조했습니다. 최대 차이 2.5µm 입니다. 즉 시뮬레이터·파이썬 스크립트·rerun 화면이 모두 같은 자세를 가리킵니다.

--urdf 를 빼면 메시 없이 뼈대와 TCP만 그립니다. 저장소를 받지 않았거나 메시를 못 읽는 환경에서도 동작합니다.

무엇을 보게 되나#

  • 왼쪽 Blueprint 패널에 엔티티 트리가 나타납니다. 메시는 so101_new_calib/visual_geometries/<링크 이름>/visual_N, 충돌 형상은 collision_geometries/… 아래에 링크별로 놓입니다
  • 3D 뷰에서 부품 위에 마우스를 올리면 어느 링크의 몇 번째 메시인지와 그 지점의 좌표가 뜹니다
  • 메시 파일을 못 찾으면 Failed to read file: assets/….stl 경고가 콘솔에 줄줄이 찍힙니다. URDF만 따로 받았을 때 흔히 겪는 일이니, 저장소를 통째로 clone 해서 assets/ 폴더가 URDF 옆에 있게 하세요
  • 원점과 축 방향이 의도대로인지가 한눈에 드러납니다
언제 rerun을 쓰나

check_urdf는 트리가 유효한지만 알려 주고, RViz2는 ROS 설치가 필요합니다. rerun은 그 사이를 메웁니다. URDF 파일 하나만 있으면 되고, 메시 경로가 깨졌는지 축이 뒤집혔는지를 즉시 눈으로 잡아냅니다. URDF를 손으로 고치는 중이라면 rerun을 띄워 놓고 작업하세요.

다만 rerun 로더는 조인트를 움직여 볼 수는 없습니다. 자세를 바꿔 보려면 아래 표의 다른 도구를 쓰세요.
