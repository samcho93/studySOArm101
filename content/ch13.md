## 정책(policy)이란

**관측(observation)을 입력받아 행동(action)을 출력하는 신경망**입니다.

```text
입력:  카메라 영상(들) + 현재 관절 상태
   ↓  [신경망]
출력:  다음에 보낼 관절 목표값
```

모방학습은 이 함수를 **사람의 시연 데이터로 지도학습**하는 것입니다.

---

## 어떤 정책을 고를까

| 정책 | 파라미터 | 학습 시간 | 데이터 요구 | 특징 |
| --- | --- | --- | --- | --- |
| **ACT** | ~80M | 짧음 (수 시간) | 50~100 ep | **SO-ARM101의 기본 선택.** Action chunking으로 부드러운 궤적 |
| **Diffusion Policy** | ~100M | 중간 | 100+ ep | 다봉 분포(같은 상황에 여러 정답)에 강함 |
| **SmolVLA** | ~450M | 김 | 50+ ep | 언어 지시 이해. 여러 작업을 한 모델로 |
| **π0 / π0.5** | 3B+ | 매우 김 | 파인튜닝 | 대규모 사전학습 VLA. 범용성 최고, 자원 소모 큼 |

@fig[act-chunking] ACT 의 핵심인 action chunking 과 temporal ensembling.

:::tip 처음이라면 무조건 ACT
ACT는 학습이 빠르고 하이퍼파라미터에 덜 민감합니다. **ACT로 성공률을 확보한 뒤** 다른 정책을 시도하세요. 원문 위키의 듀얼암 튜토리얼도 ACT를 기준으로 작성되어 있습니다.
:::

:::info Action Chunking이란
ACT의 핵심 아이디어입니다. 다음 **1개** 행동이 아니라 다음 **100개(chunk_size)** 행동을 한꺼번에 예측합니다.

- 장점: 예측이 매끄럽고, 매 스텝 추론하지 않아도 되어 지연에 강합니다.
- 단점: 예측한 청크 도중 환경이 바뀌면 대응이 늦습니다.

그래서 실제로는 여러 청크를 겹쳐 평균내는 **temporal ensembling**을 씁니다.
:::

## 기본 학습 명령

Hub 데이터셋으로:

```bash
lerobot-train \
  --dataset.repo_id=${HF_USER}/so101_pick_cube \
  --policy.type=act \
  --output_dir=outputs/train/act_so101_pick \
  --job_name=act_so101_pick \
  --policy.device=cuda \
  --wandb.enable=true \
  --policy.repo_id=${HF_USER}/my_policy
```

로컬 데이터셋으로:

```bash
lerobot-train \
  --dataset.repo_id=myname/so101_pick_cube \
  --dataset.root=./datasets/so101_pick_cube \
  --policy.type=act \
  --policy.device=cuda \
  --steps=60000 \
  --output_dir=outputs/train/act_so101_pick \
  --wandb.enable=false \
  --policy.push_to_hub=false
```

### 인자 설명

| 인자 | 의미 |
| --- | --- |
| `--dataset.repo_id` | 데이터셋 식별자. 로컬이면 `--dataset.root`와 함께 |
| `--policy.type=act` | 정책 종류. 데이터셋의 관절 수·카메라 수에 **자동으로 맞춰집니다** |
| `--policy.device` | `cuda` (NVIDIA GPU), `cpu` |
| `--steps` | 학습 스텝 수. ACT는 보통 **60,000~100,000** |
| `--output_dir` | 체크포인트 저장 경로 |
| `--wandb.enable` | Weights & Biases 로깅. 쓰려면 `wandb login` 먼저 |
| `--policy.push_to_hub` | 학습 후 Hub 업로드 여부 |

:::warn `--output_dir` 이 이미 존재하면
`FileExistsError`가 납니다. **새 디렉터리를 쓰거나** `--resume=true`로 이어서 학습하세요.
:::

## 학습 재개

로컬 체크포인트에서:

```bash
lerobot-train \
  --config_path=outputs/train/act_so101_pick/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

Hub에 푸시한 런에서 (`--save_checkpoint_to_hub=true`로 학습했다면):

```bash
lerobot-train --config_path=${HF_USER}/my_policy --resume=true
```

옵티마이저·스케줄러·스텝 카운터·데이터 순서까지 복원됩니다.

## GPU가 없을 때

### Google Colab

LeRobot은 [ACT 학습 노트북](https://huggingface.co/docs/lerobot/en/notebooks#training-act)을 제공합니다. 데이터셋을 Hub에 올려 두면 Colab에서 바로 학습할 수 있습니다.

### Hugging Face Jobs

초 단위 종량제로 클라우드 GPU에서 학습합니다.

```bash
hf auth login
lerobot-train \
  --dataset.repo_id=${HF_USER}/so101_pick_cube \
  --policy.type=act \
  --policy.repo_id=${HF_USER}/my_policy \
  --job.target=a10g-small
```

사용 가능한 하드웨어와 가격:

```bash
hf jobs hardware
```

로그는 터미널로 스트리밍되고, **Ctrl-C로 떼어내도 작업은 클라우드에서 계속 돕니다.**

```bash
hf jobs logs <job-id>
hf jobs cancel <job-id>
```

:::info 로컬 데이터셋도 됩니다
Hub에 없는 로컬 데이터셋은 **자동으로 비공개 Hub 저장소에 업로드**되어 작업이 내려받습니다. 공개되지 않습니다.
:::

기본 제한 시간은 48시간이며 `--job.timeout=4h` 처럼 조정할 수 있습니다. 중간 체크포인트도 Hub에 올리려면 `--save_checkpoint_to_hub=true`를 추가하세요.

### 클라우드 GPU 렌탈

원문 위키는 "본 튜토리얼에서는 클라우드 GPU 플랫폼으로 모델을 학습하므로 내 컴퓨터가 고사양일 필요가 없다"고 안내합니다. 국내에서도 시간당 과금 GPU 서비스를 쓰면 됩니다.

## 하이퍼파라미터 다루기

ACT 기본값(`chunk_size=100`, `dim_model=512` 등)은 대체로 잘 동작합니다. 손대야 할 때는 이 순서로 보세요.

| 상황 | 조정 |
| --- | --- |
| 학습 loss는 내려가는데 실기 성능이 나쁨 | **데이터 문제**입니다. 하이퍼파라미터가 아니라 데이터셋을 점검하세요 |
| 동작이 끊기고 튐 | `chunk_size`를 키우거나 temporal ensembling 확인 |
| 느린 동작만 배움 | 데이터의 정지 구간이 너무 긺 |
| GPU 메모리 부족 | `--batch_size` 축소 |
| 과적합 (train loss만 하락) | 데이터 다양성 확대, 스텝 수 축소 |

:::danger 하이퍼파라미터로 데이터 문제를 고칠 수 없습니다
모방학습에서 성능의 80%는 **데이터 품질**이 결정합니다. 성공률이 낮다면 우선 다음을 점검하세요.

- 에피소드 수가 충분한가? (최소 50)
- 카메라 영상만 보고 사람이 작업을 판단할 수 있는가?
- 시연이 일관적인가? (매번 다른 방식으로 잡지 않았는가)
- 실패한 시연이 섞여 있지 않은가?
:::

## 학습 모니터링

### Weights & Biases

```bash
wandb login
```

`--wandb.enable=true`로 학습하면 loss 곡선, 학습률, 샘플 이미지가 웹 대시보드에 기록됩니다.

### 읽어야 할 지표

| 지표 | 정상 패턴 |
| --- | --- |
| `loss` | 초기 급락 후 완만한 하락 |
| `l1_loss` | 행동 예측 오차. 꾸준히 감소 |
| `kld_loss` (ACT) | VAE 정규화 항. 너무 커지면 잠재 붕괴 의심 |
| 학습률 | 스케줄대로 감소 |

:::tip 언제 멈출까
loss가 평탄해졌다고 최적은 아닙니다. **여러 체크포인트(예: 20k, 40k, 60k)를 실기에서 평가**해 성공률이 가장 높은 것을 고르세요. 학습이 더 진행될수록 실기 성능이 떨어지는 경우도 흔합니다.
:::

## 체크포인트 관리

학습 결과는 다음에 저장됩니다.

```text
outputs/train/act_so101_pick/checkpoints/
├── 010000/pretrained_model/
├── 020000/pretrained_model/
└── last/pretrained_model/
```

Hub 업로드:

```bash
hf upload ${HF_USER}/act_so101_pick \
  outputs/train/act_so101_pick/checkpoints/last/pretrained_model
```

중간 체크포인트:

```bash
CKPT=010000
hf upload ${HF_USER}/act_so101_pick${CKPT} \
  outputs/train/act_so101_pick/checkpoints/${CKPT}/pretrained_model
```

비공개·태그·라이선스 지정:

```bash
--policy.private=true --policy.tags=\[act,so101\] --policy.license=mit
```

```bash

```

## 학습 시간 참고

| 환경 | ACT 60k 스텝 예상 시간 |
| --- | --- |
| RTX 4090 | 약 2~3시간 |
| RTX 3060 | 약 6~8시간 |
| HF Jobs a10g-small | 약 4~5시간 |
| CPU만 | 비현실적 |

원문 위키가 인용하는 사례로는 **15초짜리 조작 영상 50개로 2시간 학습**해 옷 개기·열쇠 꽂기·부품 분류를 습득한 예가 있습니다.
