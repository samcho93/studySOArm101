## URDF란

**URDF(Unified Robot Description Format)** 는 로봇의 구조를 기술하는 XML 파일입니다. ROS 2의 거의 모든 도구(RViz2, MoveIt 2, Gazebo, ros2_control)가 이 파일 하나를 읽고 동작합니다.

URDF가 담는 정보:

| 요소 | 내용 |
| --- | --- |
| `<link>` | 강체 부품. 시각 형상(visual), 충돌 형상(collision), 관성(inertial) |
| `<joint>` | 링크 사이 관절. 종류, 축, 원점, 한계 |
| `<material>` | 색상·텍스처 |

## SO-ARM101의 URDF 구하기

세 가지 경로가 있습니다.

| 출처 | 파일 | 특징 |
| --- | --- | --- |
| **TheRobotStudio/SO-ARM100** | `Simulation/SO101/so101_new_calib.urdf` | 공식 CAD에서 생성. 이 강좌의 기준 |
| **LeRobot 저장소** | 내부 자산 | LeRobot 시각화용 |
| **URDF Studio** | [urdf.d-robotics.cc](https://urdf.d-robotics.cc/) | 브라우저에서 URDF를 편집·확인 |

이 강좌의 저장소에는 원본이 이미 포함되어 있습니다.

```text
ros2_ws/src/so_arm101_description/urdf/so101_new_calib.urdf
```

파일 머리에는 생성 도구가 명시되어 있습니다.

```xml
<?xml version="1.0" encoding="utf-8"?>
<!-- Generated using onshape-to-robot -->
<!-- Onshape https://cad.onshape.com/documents/7715cc284bb430fe6dab4ffd/... -->
<robot name="so101_new_calib">
```

:::info onshape-to-robot
Onshape CAD 모델에서 URDF를 자동 생성하는 도구입니다. 그래서 원점 값들이 `-8.97657e-09` 처럼 지저분한 부동소수점으로 나옵니다. 사실상 0인 값들입니다.
:::

## 링크 구조

@fig[link-chain] URDF 가 정의하는 사슬. 이 장에서는 이 그림의 각 화살표가 XML 로 어떻게 적혀 있는지를 봅니다.


```text
base_link
 └─ shoulder_link
     └─ upper_arm_link
         └─ lower_arm_link
             └─ wrist_link
                 └─ gripper_link
                     ├─ moving_jaw_so101_v1_link
                     └─ gripper_frame_link   (fixed, TCP)
```

각 링크는 세 가지 형상을 가집니다.

```xml
<link name="upper_arm_link">
  <inertial>
    <origin xyz="-0.0898471 -0.00838224 0.0184089" rpy="0 0 0"/>
    <mass value="0.1"/>
    <inertia ixx="..." .../>
  </inertial>
  <visual>
    <origin xyz="-0.11257 -0.0155 0.0187" rpy="-3.14159 0 -1.5708"/>
    <geometry><mesh filename="package://so_arm101_description/meshes/upper_arm.stl"/></geometry>
    <material name="3d_printed"/>
  </visual>
  <collision>
    <origin xyz="-0.11257 -0.0155 0.0187" rpy="-3.14159 0 -1.5708"/>
    <geometry><mesh filename="package://so_arm101_description/meshes/upper_arm.stl"/></geometry>
  </collision>
</link>
```

| 요소 | 용도 | 주의 |
| --- | --- | --- |
| `visual` | RViz·Gazebo에 그려지는 모습 | 정밀한 메시 OK |
| `collision` | 충돌 검사 | **단순할수록 좋음.** 메시가 복잡하면 플래닝이 느려짐 |
| `inertial` | 물리 시뮬레이션 | Gazebo에서 필수. 값이 이상하면 로봇이 날아감 |

:::tip 충돌 형상 최적화
MoveIt 2 플래닝이 느리다면 `collision` 지오메트리를 STL 대신 **박스/실린더 프리미티브**로 바꾸는 것이 가장 효과적입니다. 이 강좌의 `so_arm101_description` 패키지는 프리미티브 버전을 xacro 옵션으로 제공합니다.
:::

## 조인트 정의 완전 해부

SO-ARM101의 6개 조인트를 URDF 원문 값 그대로 정리했습니다.

### shoulder_pan

```xml
<joint name="shoulder_pan" type="revolute">
  <origin xyz="0.0388353 -8.97657e-09 0.0624" rpy="3.14159 4.18253e-17 -3.14159"/>
  <parent link="base_link"/>
  <child  link="shoulder_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-1.91986" upper="1.91986"/>
</joint>
```

### shoulder_lift

```xml
<joint name="shoulder_lift" type="revolute">
  <origin xyz="-0.0303992 -0.0182778 -0.0542" rpy="-1.5708 -1.5708 0"/>
  <parent link="shoulder_link"/>
  <child  link="upper_arm_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-1.74533" upper="1.74533"/>
</joint>
```

### elbow_flex

```xml
<joint name="elbow_flex" type="revolute">
  <origin xyz="-0.11257 -0.028 1.73763e-16" rpy="0 0 1.5708"/>
  <parent link="upper_arm_link"/>
  <child  link="lower_arm_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-1.69" upper="1.69"/>
</joint>
```

### wrist_flex

```xml
<joint name="wrist_flex" type="revolute">
  <origin xyz="-0.1349 0.0052 3.62355e-17" rpy="0 0 -1.5708"/>
  <parent link="lower_arm_link"/>
  <child  link="wrist_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-1.65806" upper="1.65806"/>
</joint>
```

### wrist_roll

```xml
<joint name="wrist_roll" type="revolute">
  <origin xyz="0 -0.0611 0.0181" rpy="1.5708 0.0486795 3.14159"/>
  <parent link="wrist_link"/>
  <child  link="gripper_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-2.74385" upper="2.84121"/>
</joint>
```

:::info `rpy`의 0.0486795가 뭔가요
약 2.79°의 미세한 틀어짐입니다. CAD 상의 실제 조립 각도가 그대로 반영된 것입니다. 이런 값이 있기 때문에 **URDF를 손으로 다시 쓰지 말고 원본을 그대로 쓰는 것**이 좋습니다.
:::

### gripper

```xml
<joint name="gripper" type="revolute">
  <origin xyz="0.0202 0.0188 -0.0234" rpy="1.5708 -5.24284e-08 0"/>
  <parent link="gripper_link"/>
  <child  link="moving_jaw_so101_v1_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-0.174533" upper="1.74533"/>
</joint>
```

### gripper_frame_joint (TCP)

```xml
<joint name="gripper_frame_joint" type="fixed">
  <origin xyz="-0.0079 -0.000218121 -0.0981274" rpy="0 3.14159 0"/>
  <parent link="gripper_link"/>
  <child  link="gripper_frame_link"/>
  <axis xyz="0 0 0"/>
</joint>
```

:::tip TCP를 기억하세요
MoveIt 2에서 **엔드 이펙터 링크**로 지정할 것이 바로 `gripper_frame_link`입니다. IK 목표도 이 프레임을 기준으로 지정합니다.
:::

| 조인트 | 타입 | 축 | 하한(rad) | 상한(rad) | 하한(°) | 상한(°) |
| --- | --- | --- | --- | --- | --- | --- |
| `shoulder_pan` | revolute | Z | -1.91986 | 1.91986 | -110.0 | 110.0 |
| `shoulder_lift` | revolute | Z | -1.74533 | 1.74533 | -100.0 | 100.0 |
| `elbow_flex` | revolute | Z | -1.69000 | 1.69000 | -96.8 | 96.8 |
| `wrist_flex` | revolute | Z | -1.65806 | 1.65806 | -95.0 | 95.0 |
| `wrist_roll` | revolute | Z | -2.74385 | 2.84121 | -157.2 | 162.8 |

이 강좌의 시뮬레이터와 파이썬 스크립트는 위 값을 그대로 씁니다.

```bash
python scripts/so101_fk_ik.py --fk 0 -30 45 60 0
```

```text
조인트 (deg): pan=0.0  lift=-30.0  elbow=45.0  wrist_flex=60.0  wrist_roll=0.0
TCP 위치 (m): x=0.2413  y=0.0007  z=0.1702
```

역기구학:

```bash
python scripts/so101_fk_ik.py --ik 0.24 0.00 0.17
```

## xacro로 확장하기

URDF는 매크로가 없어 반복이 많습니다. ROS 2에서는 **xacro**(XML Macro)로 감싸 쓰는 것이 표준입니다.

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="so_arm101">

  <xacro:arg name="hardware_type" default="mock"/>
  <xacro:arg name="usb_port"      default="/dev/ttyACM0"/>

  <!-- 순수 기구 구조 -->
  <xacro:include filename="$(find so_arm101_description)/urdf/so101_macro.xacro"/>
  <xacro:so101_arm prefix=""/>

  <!-- ros2_control 하드웨어 인터페이스 -->
  <xacro:include filename="$(find so_arm101_description)/urdf/so101.ros2_control.xacro"/>
  <xacro:so101_ros2_control
      name="SOArm101System"
      hardware_type="$(arg hardware_type)"
      usb_port="$(arg usb_port)"/>

</robot>
```

xacro를 URDF로 펼쳐 보려면:

```bash
ros2 run xacro xacro src/so_arm101_description/urdf/so_arm101.urdf.xacro > /tmp/so101.urdf
check_urdf /tmp/so101.urdf
```

`check_urdf`는 링크·조인트 트리가 올바른지 검증하고 구조를 출력합니다.

```bash
urdf_to_graphiz /tmp/so101.urdf   # 트리 다이어그램 PDF 생성
```

## TheRobotStudio 저장소의 시뮬레이션 자산

URDF 원본이 사는 곳은 [TheRobotStudio/SO-ARM100](https://github.com/TheRobotStudio/SO-ARM100) 저장소의 `Simulation/` 폴더입니다. 저장소 이름이 **100**이지만 **SO-101 자산도 같은 곳에 함께** 들어 있습니다.

| 경로 | 내용 |
| --- | --- |
| `Simulation/SO101/so101_new_calib.urdf` | **현재 표준.** 이 강좌와 시뮬레이터가 쓰는 파일 |
| `Simulation/SO101/so101_old_calib.urdf` | 구 캘리브레이션 규약 URDF |
| `Simulation/SO101/so101_new_calib_camera.urdf` | 손목 카메라 마운트가 붙은 변형 (`wrist_camera_mount_link`·`wrist_camera_link` 2개 추가) |
| `Simulation/SO101/*.xml` | 같은 모델의 **MJCF**(MuJoCo) 버전 |
| `Simulation/SO101/scene.xml` | MuJoCo 씬 — 바닥·조명에 로봇을 include |
| `Simulation/SO101/joints_properties.xml` | 모터 파라미터 (감쇠·마찰·강성) |
| `Simulation/SO100/so100.urdf` | 구형 SO-100 URDF (**deprecated**) |
| `Simulation/SO100/so100.rrd` | rerun 녹화 파일 — 받아서 바로 재생 가능 |

### 이 URDF가 만들어진 방식 — 알아 두면 좋은 네 가지

**1. onshape-to-robot으로 생성**되었습니다. 원 설계는 Onshape CAD이고 URDF는 거기서 자동 변환된 결과입니다. 그래서 링크 이름과 좌표계가 사람이 손으로 쓴 URDF와는 조금 다른 냄새를 풍깁니다.

**2. 메시 경로가 `package://`가 아니라 상대 경로**로 바뀌어 있습니다. ROS 밖(MuJoCo·rerun·PyBullet 등)에서도 그냥 열리게 하려는 의도입니다. 뒤집어 말하면 **ROS 2 패키지로 감쌀 때는 이 경로를 `package://so_arm101_description/meshes/...` 형태로 고쳐야** 합니다. ([16장](~/lessons/ch16.html)에서 다룹니다.)

**3. 베이스의 충돌 메시가 제거**되었다고 저장소 README가 밝히고 있습니다. 시뮬레이션과 경로 계획에서 베이스 충돌 형상이 문제를 일으켰기 때문입니다.

다만 **실제로 빠져 있는 쪽은 MJCF입니다.** 파일을 직접 열어 확인한 결과는 이렇습니다.

| 파일 | `base` 링크의 충돌 형상 |
| --- | --- |
| `so101_new_calib.urdf` | **4개 그대로 있음** (base·모터 홀더·서보·마운팅 플레이트) |
| `so101_new_calib.xml` (MJCF) | **0개** — 제거됨 |

즉 **MuJoCo에서는 베이스와 팔의 충돌이 검사되지 않고**, URDF를 쓰는 RViz·MoveIt·Gazebo에서는 검사됩니다. MoveIt SRDF에서 베이스 관련 쌍을 비활성화해 두는 것도 이 충돌이 실제로 존재하기 때문입니다.

**4. 그리퍼는 아직 회전 조인트**입니다. URDF·MJCF 모두 `gripper`를 라디안 단위 revolute 조인트로 기술하지만, **LeRobot은 그리퍼를 0(닫힘)~100(열림)의 선형 값으로 다룹니다.** 저장소도 "아직 URDF/MJCF에 반영되지 않았다"고 명시해 두었습니다. 정책 출력과 URDF 조인트 값을 직접 비교할 때 이 차이를 잊지 마세요.

:::warn new_calib과 old_calib의 차이
두 URDF는 **조인트의 가상 0점을 어디에 두느냐**만 다릅니다.

- **new_calib (기본)** — 각 조인트의 0이 **가동범위의 한가운데**
- **old_calib** — 각 조인트의 0이 **팔을 수평으로 쭉 뻗은 자세**

같은 모터 값이라도 두 URDF에서 팔 모양이 다르게 나옵니다. MuJoCo에서는 `scene.xml`의 include 한 줄을 바꿔 전환합니다. 이 강좌는 **처음부터 끝까지 new_calib** 기준입니다.

그리고 0점보다 더 성가신 차이가 하나 있습니다. **링크 이름이 통째로 다릅니다.**

| new_calib | old_calib · SO-100 · MJCF |
| --- | --- |
| `base_link` | `base` |
| `shoulder_link` | `shoulder` |
| `upper_arm_link` | `upper_arm` |
| `lower_arm_link` | `lower_arm` |
| `wrist_link` | `wrist` |
| `gripper_link` | `gripper` |
| `moving_jaw_so101_v1_link` | `jaw` |
| `gripper_frame_link` (TCP) | **없음** |

old_calib에는 **TCP 프레임(`gripper_frame_link`) 자체가 없습니다.** 이 강좌의 IK·MoveIt 설정·시뮬레이터는 모두 이 프레임을 기준으로 하므로, old_calib URDF를 그대로 끼워 넣으면 **TF 조회부터 실패**합니다.
:::

:::info 모터 파라미터의 출처
`joints_properties.xml`의 감쇠·마찰 값은 **Open Duck Mini** 프로젝트의 STS3215 파라미터를 가져와 맞춘 것입니다. 실제 서보와 완전히 같지는 않으므로, Sim2Real을 할 때는 이 값을 직접 동정(system identification)하는 편이 좋습니다.
:::

## 먼저 — 설치 없이 브라우저에서 열어 보기

강좌에 **URDF 뷰어**가 들어 있습니다. 파이썬도, rerun도, ROS도 필요 없습니다.

@btn[~/tools/urdf-viewer.html] URDF 뷰어 열기

URDF 파일을 직접 파싱해 링크 트리를 만들고 `<visual>`·`<collision>` 형상을 그립니다. STL은 바이너리·ASCII 둘 다 읽습니다. rerun의 URDF visualizer가 하는 일과 같되, **조인트를 직접 움직여 볼 수 있다는 점이 다릅니다.**

여는 방법은 세 가지입니다.

| 방법 | 필요한 것 | 보이는 것 |
| --- | --- | --- |
| **내장 모델** | 없음 | 이 강좌의 기구학 값으로 만든 URDF. 형상은 상자 근사 |
| **저장소에서 받기** | 인터넷 | `so101_new_calib` / `old_calib` / `+카메라` / `SO-100` — **진짜 STL 메시까지** |
| **내 컴퓨터에서 열기** | clone 한 저장소 | `Simulation/SO101` 폴더를 고르면 URDF와 `assets/` STL을 함께 읽음 |

### 이 뷰어로 확인해 볼 것

- **`collision` 만 켜 보기** — visual을 끄면 실제로 충돌 검사에 쓰이는 형상만 남습니다. 아래에서 이야기할 "베이스 충돌 메시" 문제를 눈으로 확인할 수 있습니다
- **`old_calib` 을 열어 보기** — 같은 로봇인데 링크 이름이 전부 다르고 `gripper_frame_link`가 없습니다. 구형 자료를 그대로 가져다 쓰면 왜 깨지는지 바로 보입니다
- **링크 좌표계 켜기** — 각 링크의 x(빨강)·y(초록)·z(파랑) 축이 표시됩니다. 조인트 축이 의도한 방향인지 확인하는 가장 빠른 방법입니다
- **조인트 표** — URDF의 `origin xyz`·`axis`·`lower`/`upper`가 그대로 나옵니다. [아래 한계 요약표](#조인트-한계-요약표)와 대조해 보세요

:::info 어떤 걸 언제 쓰나
| | 브라우저 뷰어 | rerun |
| --- | --- | --- |
| 설치 | 없음 | `pip install rerun-sdk` |
| 조인트 조작 | ○ 슬라이더 | ✗ (강좌 스크립트를 쓰면 ○) |
| 궤적 재생·시계열 그래프 | ✗ | ○ |
| 충돌 형상 토글 | ○ | ○ |
| 큰 메시 처리 | 브라우저 메모리 한계 | 더 여유 있음 |

**URDF 한 개를 빠르게 확인**할 땐 브라우저 뷰어, **궤적을 재생하거나 로그와 함께 볼** 땐 rerun입니다.
:::

## rerun + URDF visualizer 플러그인으로 열어 보기

ROS를 설치하지 않고 URDF를 눈으로 확인하는 가장 빠른 방법입니다. 저장소가 공식으로 안내하는 경로이기도 합니다.

### 설치

```bash
pip install rerun-sdk
```

저장소 README는 여기에 **URDF visualizer 플러그인**을 더 깔라고 안내합니다.

```bash
pip install git+https://github.com/rerun-io/rerun-loader-python-example-urdf.git
```

rerun은 모르는 확장자를 만나면 **외부 로더**를 찾아 실행하는 구조이고, 이 플러그인이 `.urdf` 를 담당하는 외부 로더입니다.

:::tip 최신 rerun에서는 플러그인이 필요 없습니다
**rerun 0.38 기준으로 URDF 지원이 rerun 자체에 들어왔습니다.** 플러그인을 PATH에서 완전히 치운 상태로 확인해 본 결과, `rerun so101_new_calib.urdf` 만으로 메시 17개가 그대로 올라옵니다.

버전을 확인해 보세요.

```bash
rerun --version
```

- **0.38 이상** — `pip install rerun-sdk` 만으로 충분합니다
- **그 이하** — 플러그인을 설치해야 하고, `rerun-loader-urdf` 실행 파일이 **PATH에 있어야** 합니다. 가상환경에 깔았다면 그 환경을 활성화한 셸에서 rerun을 실행하세요

```bash
which rerun-loader-urdf     # Windows: where rerun-loader-urdf
```

플러그인 방식에서 이 명령이 아무것도 내놓지 않으면, 뷰어는 URDF를 "모르는 파일"로 취급하고 아무것도 그리지 않습니다.
:::

### 실행

```bash
git clone https://github.com/TheRobotStudio/SO-ARM100.git
cd SO-ARM100

rerun Simulation/SO101/so101_new_calib.urdf   # 현재 표준
rerun Simulation/SO101/so101_old_calib.urdf   # 구 캘리브레이션
rerun Simulation/SO100/so100.urdf             # 구형 SO-100
```

저장소에 들어 있는 녹화 파일도 같은 방식으로 열립니다.

```bash
rerun Simulation/SO100/so100.rrd
```

### 시뮬레이터도 이 메시로 그립니다

[3D 시뮬레이터](~/sim/index.html)와 [홈 화면의 미니 뷰어](~/index.html) 모두 **이 URDF의 실제 메시**로 그립니다. 예전의 상자 근사가 아닙니다.

홈 화면은 두 단계로 뜹니다. 먼저 받을 것이 없는 **2D 캔버스**로 즉시 그리고, 페이지가 다 뜬 뒤에 three.js와 번들을 받아 **WebGL로 조용히 갈아끼웁니다.** 첫 화면이 비어 있는 순간이 없고, 내려받기가 첫 표시를 늦추지도 않습니다. 브라우저가 데이터 절약 모드면 2D 그대로 둡니다.

STL 13개를 그대로 쓰면 16MB라 브라우저에 지우기엔 무겁습니다. 그래서 `scripts/build_meshes.py`가 한 번 줄여 둔 번들(`assets/mesh/so101-meshes.bin`, **1.47MB**)을 씁니다.

```bash
python scripts/build_meshes.py --download      # 저장소에서 받아 번들 생성
python scripts/build_meshes.py --repo ../SO-ARM100
```

줄이는 방법은 세 단계입니다.

1. 정점을 **0.2mm 격자**로 반올림해 같은 점을 하나로 합칩니다 (STL은 삼각형마다 정점을 중복 저장합니다)
2. 좌표를 메시 최소점 기준 **uint16** 정수로 저장합니다 — 정점당 12바이트가 6바이트로
3. 법선을 아예 빼고 브라우저에서 `flatShading`으로 그립니다

| 형식 | 삼각형 | 크기 |
| --- | --- | --- |
| 원본 STL 13개 | 322,564 | 16.13MB |
| 정점 중복만 제거 | 322,564 | 3.86MB |
| **0.2mm 번들 (사용 중)** | 163,157 | **1.47MB** |

:::warn 0.5mm까지 줄이면 안 됩니다
같은 방식으로 0.5mm 격자까지 밀면 1.04MB가 되지만, **평평해야 할 면이 눈에 띄게 울퉁불퉁해집니다.** 0.2mm는 화면에서 원본과 구분되지 않습니다. 직접 확인해 보려면 [URDF 뷰어](~/tools/urdf-viewer.html)에 원본과 줄인 파일을 번갈아 넣어 보세요.
:::

:::info 같은 데이터를 두 벌로 내보냅니다
`build_meshes.py` 는 `.bin` 과 함께 **`so101-meshes.b64.js`(1.96MB)** 도 만듭니다. 내용은 같고 base64로 담았을 뿐입니다.

Artifact처럼 **`.bin` 확장자를 서빙하지 않는 곳**이 있어서입니다. 로더는 `.bin` 을 먼저 받아 보고, 실패하면 이 스크립트를 불러옵니다. 평소에는 받지 않으므로 느려지지 않습니다.
:::

번들을 둘 다 못 읽으면 시뮬레이터는 **예전 상자 근사로 되돌아가** 계속 동작합니다. 기구학은 어느 쪽이든 같으므로 숫자는 달라지지 않습니다.

### 강좌 스크립트로 움직여 보기

뷰어로 URDF를 여는 것만으로는 **자세를 바꿀 수 없습니다.** 강좌에 포함된 스크립트가 이 부분을 채웁니다.

```bash
cd scripts

# 기본 자세 하나
python rerun_view_so101.py --urdf ../SO-ARM100/Simulation/SO101/so101_new_calib.urdf

# 관절을 하나씩 한계까지 흔들기 — 가동범위를 눈으로 확인할 때
python rerun_view_so101.py --urdf .../so101_new_calib.urdf --sweep

# 브라우저 시뮬레이터에서 녹화한 궤적 재생
python rerun_view_so101.py --urdf .../so101_new_calib.urdf     --trajectory so101_trajectory.json

# 화면 대신 파일로 저장 (나중에 rerun sweep.rrd 로 열기)
python rerun_view_so101.py --urdf .../so101_new_calib.urdf --sweep --save sweep.rrd
```

스크립트는 URDF를 싣고, 이 강좌의 기구학(, [2장](~/lessons/ch02.html))으로 계산한 각 조인트 변환을 매 프레임 다시 실어 **메시를 실제로 움직입니다.** 함께 그려지는 것은 뼈대, TCP 점, 그리고 아래쪽 패널의 조인트·TCP 시계열 그래프입니다.

:::check 두 계산이 일치하는지 확인했습니다
rerun이 URDF에서 직접 계산한 조인트 변환을 체인으로 이어 TCP를 구한 값과, 이 강좌의 `so101_kinematics.py` 가 구한 TCP 값을 6개 기본 자세에서 대조했습니다. **최대 차이 2.5µm** 입니다. 즉 시뮬레이터·파이썬 스크립트·rerun 화면이 모두 같은 자세를 가리킵니다.
:::

`--urdf` 를 빼면 메시 없이 뼈대와 TCP만 그립니다. 저장소를 받지 않았거나 메시를 못 읽는 환경에서도 동작합니다.

### 무엇을 보게 되나

- 왼쪽 **Blueprint** 패널에 엔티티 트리가 나타납니다. 메시는 `so101_new_calib/visual_geometries/<링크 이름>/visual_N`, 충돌 형상은 `collision_geometries/…` 아래에 링크별로 놓입니다
- 3D 뷰에서 부품 위에 마우스를 올리면 **어느 링크의 몇 번째 메시인지**와 그 지점의 좌표가 뜹니다
- 메시 파일을 못 찾으면 `Failed to read file: assets/….stl` 경고가 콘솔에 줄줄이 찍힙니다. **URDF만 따로 받았을 때 흔히 겪는 일**이니, 저장소를 통째로 clone 해서 `assets/` 폴더가 URDF 옆에 있게 하세요
- 원점과 축 방향이 의도대로인지가 한눈에 드러납니다

:::tip 언제 rerun을 쓰나
`check_urdf`는 **트리가 유효한지**만 알려 주고, RViz2는 **ROS 설치가 필요**합니다. rerun은 그 사이를 메웁니다. URDF 파일 하나만 있으면 되고, 메시 경로가 깨졌는지 축이 뒤집혔는지를 즉시 눈으로 잡아냅니다. URDF를 손으로 고치는 중이라면 rerun을 띄워 놓고 작업하세요.

다만 rerun 로더는 **조인트를 움직여 볼 수는 없습니다.** 자세를 바꿔 보려면 아래 표의 다른 도구를 쓰세요.
:::
