## Gazebo를 쓰는 이유

RViz2와 MoveIt의 Mock 모드는 **물리를 모릅니다.** 중력도, 마찰도, 관성도 없습니다. 명령한 대로 링크가 움직일 뿐입니다.

Gazebo는 물리 엔진 위에서 돌기 때문에 다음을 검증할 수 있습니다.

- 팔이 **중력을 이기고 자세를 유지**할 수 있는가
- 그리퍼가 물체를 **실제로 잡을 수 있는가** (마찰)
- 빠른 동작 시 **관성으로 흔들리지** 않는가
- 물체가 **넘어지거나 굴러가지** 않는가

:::info Gazebo 버전
- **Gazebo Classic** (gazebo11) — 구버전, Humble에서 여전히 널리 쓰임
- **Gazebo Sim / Harmonic** (gz-sim8) — 신버전, Jazzy의 기본. 브릿지는 `ros_gz` 패키지

이 강좌는 **`gz_ros2_control`** 기반 구성을 다룹니다.
:::

### 설치

Humble + Gazebo Fortress/Harmonic:

```bash
sudo apt install ros-humble-ros-gz ros-humble-gz-ros2-control
```

Jazzy + Gazebo Harmonic:

```bash
sudo apt install ros-jazzy-ros-gz ros-jazzy-gz-ros2-control
```

## Gazebo 실행 — 터미널 4개

:::warn 순서를 반드시 지키세요
Gazebo 구성은 4개의 터미널을 순서대로 실행해야 합니다. 순서가 틀리면 컨트롤러가 활성화되지 않습니다.
:::

### 터미널 1 — Gazebo 시뮬레이션 시작

```bash
source ~/so101_ws/install/setup.bash
ros2 launch so_arm_gz so_arm_gz_bringup.launch.py
```

Gazebo 창이 뜨고, 로봇이 공중에 잠시 떠 있다가 바닥에 내려앉습니다. 이 과정이 끝날 때까지 기다리세요.

### 터미널 2 — 궤적 컨트롤러 전환

Gazebo는 기본적으로 `forward_position_controller`만 활성화합니다. `joint_trajectory_controller`로 수동 전환해야 합니다.

```bash
source ~/so101_ws/install/setup.bash

# 단계 A — forward_position_controller 비활성화
ros2 control set_controller_state forward_position_controller inactive

# 단계 B — spawner로 joint_trajectory_controller 로드 + 활성화
ros2 run controller_manager spawner joint_trajectory_controller

# 단계 C — 검증
ros2 control list_controllers
```

기대 출력:

```text
forward_position_controller  inactive
joint_state_broadcaster      active
joint_trajectory_controller  active
```

:::danger `ros2 control load_controller` 를 먼저 쓰지 마세요
`load_controller`를 먼저 실행하면 컨트롤러가 **`unconfigured` 상태**가 되어 `spawner`가 활성화하지 못합니다.

이미 그렇게 했다면 먼저 언로드하고 다시 시작하세요.
```bash
ros2 control unload_controller joint_trajectory_controller
```
:::

### 터미널 3 — move_group

```bash
source ~/so101_ws/install/setup.bash
ros2 launch so_arm101_moveit_config move_group.launch.py use_sim_time:=True
```

:::warn `use_sim_time:=True` 를 빠뜨리지 마세요
Gazebo는 자체 시뮬레이션 시계를 씁니다. 이 인자가 없으면 MoveIt이 실제 시간을 기준으로 동작해 궤적 타이밍이 어긋납니다.
:::

### 터미널 4 — RViz

```bash
source ~/so101_ws/install/setup.bash
ros2 launch so_arm101_moveit_config moveit_rviz.launch.py
```

RViz가 준비되면:

1. **Planning Group → `manipulator`**
2. **Goal State → `open`** (또는 `extended`, `rest`)
3. **Plan → Execute**

Gazebo 안의 팔 관절이 함께 움직입니다.

```bash
  gazebo_gui:=false \

```

## 알려진 제약

:::warn Gazebo에서 그리퍼가 안 움직입니다
`gz_ros2_control`의 Humble 버전은 **PID 게인이 0.1로 하드코딩**되어 있어 URDF 파라미터로 덮어쓸 수 없습니다. 그 결과 그리퍼를 여는 궤적이 **실행 로그에는 성공으로 찍히지만 물리 시뮬레이션에서는 실제로 벌어지지 않습니다.**

**Mock 모드와 실기에서는 이 문제가 없습니다.** Gazebo에서 파지 실험이 꼭 필요하다면 최신 `gz_ros2_control`을 소스 빌드하거나 Gazebo Classic의 `gazebo_ros2_control`을 검토하세요.
:::

## 반복 로드 실패 시 초기화

`spawner`가 계속 `Failed to activate controller`를 낸다면 완전 초기화합니다.

```bash
# 1. 걸린 컨트롤러 언로드
ros2 control unload_controller joint_trajectory_controller

# 2. forward_position_controller 비활성화
ros2 control set_controller_state forward_position_controller inactive

# 3. 다시 spawn
ros2 run controller_manager spawner joint_trajectory_controller
```

그래도 안 되면 모든 터미널을 종료하고 터미널 1부터 다시 시작하세요.

## Gazebo 월드에 물체 추가

픽앤플레이스를 실험하려면 잡을 물체가 필요합니다.

```xml
<!-- so_arm_gz/worlds/table_with_cube.sdf -->
<model name="cube">
  <pose>0.22 0.0 0.025 0 0 0</pose>
  <link name="link">
    <inertial>
      <mass>0.05</mass>
      <inertia><ixx>2.1e-5</ixx><iyy>2.1e-5</iyy><izz>2.1e-5</izz>
               <ixy>0</ixy><ixz>0</ixz><iyz>0</iyz></inertia>
    </inertial>
    <collision name="collision">
      <geometry><box><size>0.04 0.04 0.04</size></box></geometry>
      <surface>
        <friction><ode><mu>1.2</mu><mu2>1.2</mu2></ode></friction>
      </surface>
    </collision>
    <visual name="visual">
      <geometry><box><size>0.04 0.04 0.04</size></box></geometry>
      <material><ambient>0.1 0.1 0.1 1</ambient></material>
    </visual>
  </link>
</model>
```

:::tip 마찰 계수가 핵심입니다
그리퍼가 물체를 잡지 못한다면 `mu` 값을 올려 보세요. 실제 PLA 그리퍼 + 고무 패드 조합은 대략 `mu = 1.0~1.5` 수준입니다. 너무 낮으면 미끄러지고, 너무 높으면 비현실적으로 달라붙습니다.
:::

## 시각화 도구 모음

### RViz2

ROS 2의 기본 시각화 도구입니다. 로봇 모델, TF, 궤적, 센서 데이터를 봅니다.

```bash
rviz2
```

### Foxglove Studio

브라우저/데스크톱에서 ROS 2 데이터를 보는 현대적 도구입니다. 웹에서 원격 접속할 수 있고 레이아웃이 유연합니다.

```bash
sudo apt install ros-humble-foxglove-bridge
ros2 launch foxglove_bridge foxglove_bridge_launch.xml
```

Foxglove Studio에서 `ws://localhost:8765`로 접속합니다.

:::tip LeRobot과 Foxglove
LeRobot의 시각화도 Foxglove로 스트리밍할 수 있습니다. ([10장](~/lessons/ch10.html))
```python
init_visualization("foxglove", session_name="teleoperation")
```
ROS 2 토픽과 LeRobot 관측값을 **한 화면에서** 볼 수 있습니다.
:::

### PlotJuggler

시계열 데이터를 정밀하게 분석하는 도구입니다. 관절 추종 오차 분석에 탁월합니다.

```bash
sudo apt install ros-humble-plotjuggler-ros
ros2 run plotjuggler plotjuggler
```

**Start → ROS2 Topic Subscriber** 로 `/joint_states`를 구독하면 각 관절의 position/velocity/effort를 그래프로 볼 수 있습니다.

:::task 실습 — 추종 오차 분석
1. PlotJuggler에서 `/joint_states/position/elbow_flex` 와
   `/joint_trajectory_controller/controller_state/reference/positions[2]` 를 같은 축에 올립니다.
2. MoveIt으로 빠른 동작을 실행합니다.
3. 두 곡선의 간격이 **추종 오차**입니다.

속도를 올릴수록 오차가 커지는 것을 확인하세요. 실기에서 `joint_limits.yaml`의 `max_velocity`를 어디까지 올려도 되는지 판단하는 근거가 됩니다.
:::

### rqt 도구 모음

```bash
# 노드·토픽 그래프
rqt_graph

# 토픽 값 실시간 표시
ros2 run rqt_topic rqt_topic

# 파라미터 편집
ros2 run rqt_reconfigure rqt_reconfigure

# 로그 뷰어
ros2 run rqt_console rqt_console
```

### rerun — 설치 2줄짜리 URDF·녹화 뷰어

`pip install rerun-sdk` 하나면 ROS 없이 URDF를 3D로 확인할 수 있습니다. (rerun 0.38부터는 URDF 지원이 내장이라 별도 플러그인이 필요 없습니다. 자세한 내용은 [15장](~/lessons/ch15.html#rerun-urdf-visualizer-플러그인으로-열어-보기).)

```bash
rerun Simulation/SO101/so101_new_calib.urdf
```

URDF를 고치는 중에 **메시 경로·축 방향을 즉시 확인**하는 용도로 가장 빠릅니다. 자세를 바꿔 가며 보려면 강좌 스크립트를 쓰세요.

```bash
python scripts/rerun_view_so101.py --urdf .../so101_new_calib.urdf --sweep
```

### MuJoCo — 저장소가 함께 제공하는 MJCF

TheRobotStudio 저장소의 `Simulation/SO101/` 에는 URDF와 **같은 모델의 MJCF**가 들어 있습니다. Gazebo보다 가볍고 스텝이 빨라 **제어 알고리즘을 빠르게 반복**할 때 유리합니다.

```bash
pip install mujoco
git clone https://github.com/TheRobotStudio/SO-ARM100.git
python -m mujoco.viewer --mjcf=SO-ARM100/Simulation/SO101/scene.xml
```

- `scene.xml` 은 바닥·조명에 로봇 모델을 include 하는 껍데기입니다. include 한 줄을 바꾸면 `new_calib` ↔ `old_calib` ↔ `_camera` 변형으로 전환됩니다.
- 모터의 감쇠·마찰 값은 `joints_properties.xml` 에 있고, **Open Duck Mini** 의 STS3215 파라미터에서 가져온 값입니다. 실기와 정확히 같지는 않다는 점을 전제로 쓰세요.
- ROS 2 연동은 Gazebo만큼 매끄럽지 않습니다. **ros2_control 파이프라인을 검증할 목적이라면 Gazebo**를 쓰세요.

### 이 강좌의 브라우저 시뮬레이터

설치 없이 즉시 기구학을 확인해야 할 때 가장 빠릅니다.

- [3D 시뮬레이터](~/sim/index.html) — FK/IK, 텔레오퍼레이션, 궤적 녹화, 손목 카메라 뷰
- **ROS 2 탭**에서 현재 자세를 `sensor_msgs/JointState` JSON으로 출력할 수 있어, 실제 토픽 값과 비교하기 좋습니다.

## 시뮬레이션 전략 정리

| 목적 | 최적 도구 |
| --- | --- |
| 기구학 개념 이해, 궤적 스케치 | **브라우저 시뮬레이터** |
| URDF 검증, TF 확인 | **RViz2 + joint_state_publisher_gui** |
| 경로 계획, 충돌 회피 로직 | **MoveIt 2 Mock 모드** |
| 물리 검증(중력·마찰·관성) | **Gazebo** |
| 대규모 학습 데이터 생성 | **Isaac Lab / LeIsaac** ([12장](~/lessons/ch12.html)) |
| 제어 알고리즘 빠른 반복 | **MuJoCo** (`Simulation/SO101/scene.xml`) |
| URDF 파일 자체를 눈으로 검수 | **rerun + URDF 로더** ([15장](~/lessons/ch15.html)) |

:::tip 단계적 검증이 가장 안전합니다
브라우저 시뮬 → RViz Mock → Gazebo → 실기 순서로 올라가세요. 각 단계에서 걸러지는 버그의 종류가 다릅니다. 실기에서 처음 발견하는 버그가 가장 비쌉니다.
:::
