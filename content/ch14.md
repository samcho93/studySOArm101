## 중요한 변경 사항부터

:::danger `lerobot-record`로는 더 이상 정책을 배포할 수 없습니다
예전 버전에서는 `lerobot-record --control.policy.path=...` 로 평가했지만, **현재 버전의 `lerobot-record`는 시연 데이터 수집 전용**입니다. `--policy.path`를 받지 않고 `eval_` 접두사 데이터셋 이름도 거부합니다.

배포와 평가는 **`lerobot-rollout`** 을 사용합니다.
:::

---

## `lerobot-rollout` 전략

`--strategy.type`으로 실행 모드를 고릅니다.

| 전략 | 동작 | 언제 쓰나 |
| --- | --- | --- |
| **`base`** | 자율 실행, **데이터 기록 없음** | 빠른 동작 확인 |
| **`episodic`** | 에피소드 단위 실행 + 리셋 구간 | 성공률 측정, 평가 데이터 수집 |
| **`sentry`** | 연속 기록 + 자동 업로드 | 대규모 평가 |
| **`highlight`** | 링 버퍼 기록, 키 입력 시 저장 | 흥미로운 순간만 포착 |
| **`dagger`** | 사람 개입(human-in-the-loop) 데이터 수집 | 실패 케이스 보강 |

---

## 1단계 — 빠른 동작 확인 (`base`)

먼저 데이터 기록 없이 정책이 돌아가는지만 봅니다.

```bash
lerobot-rollout \
  --strategy.type=base \
  --policy.path=outputs/train/act_so101_pick/checkpoints/last/pretrained_model \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=my_awesome_follower_arm \
  --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
  --task="Grab the black cube" \
  --duration=60
```

Hub의 모델을 쓸 수도 있습니다.

```bash
--policy.path=${HF_USER}/my_policy
```

특정 체크포인트를 지정하려면 (푸시된 체크포인트는 스텝 번호로 태깅됩니다):

```bash
--policy.pretrained_revision=010000
```

:::danger 첫 자율 주행 안전 수칙
정책은 **예측 불가능하게 움직일 수 있습니다.** 학습이 덜 됐거나 분포 밖 상황이면 팔이 갑자기 테이블을 치거나 자기 몸을 때릴 수 있습니다.

1. 작업 공간을 완전히 비우고 **사람은 팔 반경 밖**에 있으세요.
2. **전원 플러그를 손에 쥐고** 시작하세요.
3. 처음에는 `--duration=10` 정도의 짧은 시간으로 시작하세요.
4. `--interactive=true`를 주면 터미널에서 `/stop`, `/reset` 명령으로 중간에 개입할 수 있습니다.
:::

:::warn 카메라 설정이 학습 때와 같아야 합니다
카메라 **이름**(`front`, `wrist` 등)과 **해상도**가 데이터셋과 다르면 정책이 엉뚱하게 동작합니다. 녹화 때 쓴 설정을 그대로 복사하세요.
:::

## 2단계 — 성공률 측정 (`episodic`)

에피소드 단위로 실행하고 결과를 데이터셋으로 남깁니다.

```bash
lerobot-rollout \
  --strategy.type=episodic \
  --policy.path=outputs/train/act_so101_pick/checkpoints/last/pretrained_model \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.id=my_awesome_follower_arm \
  --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
  --dataset.repo_id=myname/rollout_so101_pick \
  --dataset.root=./datasets/rollout_so101_pick \
  --dataset.no_stamp=true \
  --dataset.push_to_hub=false \
  --dataset.single_task="Grab the black cube" \
  --dataset.num_episodes=10
```

:::warn 데이터셋 이름은 `rollout_` 으로 시작해야 합니다
현재 버전의 강제 규약입니다. `eval_` 접두사는 거부됩니다. 로컬 저장 시 `--dataset.root`와 `--dataset.no_stamp=true`를 함께 쓰는 것을 권장합니다.
:::

### 3단계 — 대규모 평가 (`sentry`)

```bash
lerobot-rollout \
  --strategy.type=sentry \
  --strategy.upload_every_n_episodes=5 \
  --policy.path=${HF_USER}/my_policy \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --robot.cameras="{ up: {type: opencv, index_or_path: /dev/video10, width: 640, height: 480, fps: 30}}" \
  --dataset.repo_id=${HF_USER}/rollout_so101_pick \
  --dataset.single_task="Grab the black cube" \
  --duration=600
```

## 느린 VLA를 위한 RTC 추론

π0, π0.5, SmolVLA처럼 추론이 느린 모델은 매 스텝 추론이 불가능합니다. **RTC(real-time chunking)** 를 켜면 청크를 겹쳐 부드럽게 실행합니다.

```bash
--inference.type=rtc
```

모든 전략에서 사용할 수 있습니다.

## 성공률 측정하기

### 평가 프로토콜을 정하세요

:::tip 재현 가능한 평가의 조건
1. **에피소드 수를 고정**합니다. 최소 20회.
2. **초기 조건을 명시**합니다. "큐브를 A/B/C/D/E 5개 지점에 각 4회씩."
3. **성공 기준을 미리 정의**합니다. "큐브가 상자 안에 완전히 들어가면 성공."
4. **제한 시간**을 둡니다. "30초 내 성공하지 못하면 실패."
5. **사람이 개입하지 않습니다.**
:::

```bash
python scripts/eval_success_rate.py \
  --dataset.root=./datasets/rollout_so101_pick \
  --annotate
```

에피소드를 하나씩 재생하며 성공/실패를 라벨링하고 통계를 내는 보조 스크립트입니다.

### 결과 기록 양식

| 체크포인트 | 시도 | 성공 | 성공률 | 주요 실패 양상 |
| --- | --- | --- | --- | --- |
| 20k | 20 | 7 | 35% | 파지 위치가 얕음 |
| 40k | 20 | 14 | 70% | 좌측 위치에서 실패 |
| 60k | 20 | 12 | 60% | 과적합 의심 |

이런 표를 만들면 **어느 체크포인트를 쓸지, 어떤 데이터를 보강할지**가 자명해집니다.

## 실패 분석과 데이터 보강 루프

모방학습은 한 번에 끝나지 않습니다. 이 루프를 돕니다.

```text
[평가] → [실패 패턴 파악] → [해당 상황 데이터 추가 수집] → [재학습] → [평가] ...
```

### 실패 패턴별 처방

| 실패 양상 | 원인 추정 | 처방 |
| --- | --- | --- |
| 물체 근처까지 가지만 못 잡음 | 파지 직전 정밀도 부족 | **손목 카메라** 추가 / 파지 순간 데이터 증가 |
| 특정 위치에서만 실패 | 그 위치 데이터 부족 | 해당 위치 에피소드 10개 추가 |
| 물체를 아예 못 찾음 | 전역 카메라 시야 문제 | 카메라 재배치 후 **전체 재수집** |
| 잡았다가 놓침 | 그리퍼 힘 부족 / 조기 개방 | 파지 유지 구간을 길게 시연 |
| 움직임이 떨림 | 학습 부족 또는 데이터 노이즈 | 스텝 증가, 저품질 에피소드 삭제 |
| 초반엔 잘하다 중간에 멈춤 | 분포 밖 상태(covariate shift) | **DAgger 전략**으로 복구 데이터 수집 |
| 아무 상황에서나 같은 동작 | 관측을 무시하고 평균 궤적만 학습 | 데이터 다양성 증가, 카메라 입력 확인 |

### DAgger — 사람 개입 데이터 수집

정책이 실패로 향하는 순간 사람이 개입해 올바른 행동을 보여주는 방식입니다. 분포 밖 상태에서의 복구를 배우게 하는 데 매우 효과적입니다.

```bash
lerobot-rollout \
  --strategy.type=dagger \
  --policy.path=outputs/train/act_so101_pick/checkpoints/last/pretrained_model \
  --robot.type=so101_follower \
  --robot.port=/dev/ttyACM0 \
  --teleop.type=so101_leader \
  --teleop.port=/dev/ttyACM1 \
  --dataset.repo_id=myname/rollout_dagger_pick \
  --dataset.root=./datasets/rollout_dagger_pick
```

수집한 데이터를 원래 데이터셋과 합쳐 재학습하면 성공률이 크게 오르는 경우가 많습니다.

## 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| `--policy.path` 인식 안 됨 | `lerobot-record`를 씀 | `lerobot-rollout` 사용 |
| `eval_` 접두사 거부 | 현재 버전 규약 | `rollout_` 로 시작하는 이름 사용 |
| 팔이 즉시 이상한 자세로 감 | 캘리브레이션 id 불일치 | 학습 때와 같은 `--robot.id` 사용 |
| 정책이 전혀 반응 안 함 | 카메라 이름 불일치 | 데이터셋의 `observation.images.*` 이름 확인 |
| 동작이 뚝뚝 끊김 | 추론 속도 < 제어 주기 | `--inference.type=rtc` 사용 |
| 시뮬에선 되는데 실기에서 안 됨 | Sim2Real 격차 | 실기 데이터로 파인튜닝 ([12장](~/lessons/ch12.html)) |
| 성공률이 들쭉날쭉 | 평가 프로토콜 미고정 | 초기 조건·성공 기준을 문서화 |

다음 파트(15~20장)는 완전히 다른 축입니다. LeRobot은 **학습 기반 제어**에 특화되어 있지만, 산업 현장과 연구실의 공용어는 **ROS 2**입니다. 경로 계획, 충돌 회피, 다중 로봇 협조, 표준 시뮬레이션이 필요하다면 ROS 2 스택으로 가야 합니다.

:::info LeRobot과 ROS 2는 경쟁이 아닙니다
LeRobot 생태계가 함께 쓰는 DORA 데이터플로 엔진은 **코드 핫 리로드**로 재시작 없이 정책을 조정할 수 있다는 실용적인 장점이 있습니다. (원문 위키는 "파이썬 실행 성능이 ROS 2보다 17배 빠르다"고 소개하지만 제조사 측 주장이며 측정 조건이 공개되어 있지 않으니 그대로 받아들이지는 마세요.) 반면 ROS 2는 **모션 플래닝·충돌 회피·표준 시뮬레이션·도구 생태계**에서 압도적입니다.

[20장](~/lessons/ch20.html)에서 두 세계를 잇는 브릿지를 만듭니다.
:::
