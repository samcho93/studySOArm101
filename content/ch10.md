## 카메라가 모방학습의 절반이다

모방학습 정책의 입력은 **관절 상태 + 카메라 영상**입니다. 관절 상태는 서보가 정확히 알려주지만, 카메라는 여러분이 어떻게 배치하느냐에 따라 성능이 극적으로 달라집니다.

:::tip 좋은 카메라 배치의 판별 기준
> **"카메라 영상만 보고 여러분이 직접 그 작업을 수행할 수 있는가?"**

할 수 없다면 정책도 할 수 없습니다. 물체가 가려지거나, 그리퍼가 프레임 밖으로 나가거나, 깊이 감각이 전혀 없다면 카메라를 다시 배치해야 합니다.
:::

---

## 표준 2카메라 구성

SO-ARM101의 기본 구성은 **손목 카메라 + 전역 카메라** 조합입니다.

| 위치 | 이름 예시 | 보는 것 | 역할 |
| --- | --- | --- | --- |
| **손목(wrist)** | `wrist` | 그리퍼 바로 앞 | 파지 직전 정밀 정렬 |
| **전역(top/front)** | `top`, `front` | 작업 공간 전체 | 물체 탐색, 전체 맥락 |

원문 위키는 이를 **"말단 카메라가 근거리 파지 장면을 세밀하게 잡고, 전역 카메라가 작업 환경 전체를 담아내며, 두 영상을 합쳐 입체적인 상황 인식을 만든다"** 는 취지로 설명합니다.

:::info 전역 카메라 각도
- **상단(top)**: 물체 위치를 x-y 평면에서 잘 보여줍니다. 테이블 작업에 유리.
- **정면(front)**: 높이(z)를 잘 보여줍니다. 쌓기·삽입 작업에 유리.
- 둘 중 하나만 쓴다면 **작업의 주된 오차 방향**을 보여주는 쪽을 고르세요.
:::

---

@fig[camera-layout] 두 카메라가 보는 것이 다릅니다. 전역 카메라는 **로봇이 아니라 별도 스탠드**에 고정하세요.

## 카메라 찾기

```bash
lerobot-find-cameras opencv
```

연결된 카메라의 인덱스와 지원 해상도를 보여줍니다.

```text
Camera #0: /dev/video0  (1920x1080 @30fps, 1280x720 @30fps, 640x480 @30fps)
Camera #2: /dev/video2  (640x480 @30fps)
```

RealSense 계열은:

```bash
lerobot-find-cameras realsense
```

:::warn Linux의 video 인덱스
Linux에서는 카메라 하나가 `/dev/video0`과 `/dev/video1` **두 개로 잡히는 경우가 흔합니다**(영상 스트림 + 메타데이터). 실제 영상이 나오는 쪽은 보통 **짝수 번호**입니다. `lerobot-find-cameras`가 알려주는 값을 그대로 쓰세요.

인덱스는 USB 재연결 시 바뀔 수 있습니다. 고정하려면 `/dev/v4l/by-id/...` 경로를 `index_or_path`에 직접 넣으면 됩니다.
:::

## 카메라를 붙여 텔레오퍼레이션

```bash
lerobot-teleoperate \
    --robot.type=so101_follower \
    --robot.port=/dev/ttyACM0 \
    --robot.id=my_follower_arm \
    --robot.cameras="{front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/ttyACM1 \
    --teleop.id=my_leader_arm \
    --display_data=true
```

카메라 두 대:

```bash
--robot.cameras="{ \
  wrist: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}, \
  top:   {type: opencv, index_or_path: 2, width: 640, height: 480, fps: 30} \
}"
```

RealSense를 섞어 쓰는 경우:

```bash
--robot.cameras="{ \
  up:   {type: opencv, index_or_path: /dev/video10, width: 640, height: 480, fps: 30}, \
  side: {type: intelrealsense, serial_number_or_name: 233522074606, width: 640, height: 480, fps: 30} \
}"
```

### 파이썬 API

```python
from lerobot.cameras.opencv import OpenCVCameraConfig
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig

robot_config = SO101FollowerConfig(
    port="/dev/ttyACM0",
    id="my_follower_arm",
    cameras={
        "wrist": OpenCVCameraConfig(index_or_path=0, width=640, height=480, fps=30),
        "top":   OpenCVCameraConfig(index_or_path=2, width=640, height=480, fps=30),
    },
)
```

:::warn 카메라 이름이 곧 데이터셋 컬럼명입니다
`wrist`, `top` 같은 키가 데이터셋의 `observation.images.wrist` 컬럼이 됩니다. **녹화·학습·추론에서 이름이 반드시 일치**해야 합니다. 중간에 이름을 바꾸면 이전 데이터셋으로 학습한 모델을 쓸 수 없습니다.
:::

## 해상도와 FPS 선택

| 설정 | 권장 | 이유 |
| --- | --- | --- |
| 해상도 | **640×480** | 정책 입력은 보통 224×224로 리사이즈됨. 더 키워도 학습 이득이 적고 디스크·대역폭만 소모 |
| FPS | **30** | 데이터셋 fps와 맞춰야 함 |
| 카메라 수 | **1~2대** | 3대 이상은 USB 대역폭 문제 발생 |

:::danger USB 대역폭 주의
USB 2.0 허브 하나에 카메라 2대 + 서보 보드 2개를 물리면 **영상 프레임 드롭이나 시리얼 통신 끊김**이 발생합니다.

- 카메라는 가능하면 **PC의 서로 다른 USB 컨트롤러**에 나눠 꽂으세요.
- MJPEG 지원 카메라를 쓰면 대역폭을 크게 줄일 수 있습니다.
- 노트북이라면 **USB 3.0 포트**를 우선 사용하세요.
:::

전역 카메라만 고해상도로 쓰고 싶다면:

```bash
--robot.cameras="{ \
  front: {type: opencv, index_or_path: 0, width: 1920, height: 1080, fps: 30}, \
  wrist: {type: opencv, index_or_path: 2, width: 640,  height: 480,  fps: 30} \
}"
```

## 시각화 도구

### rerun (기본)

`--display_data=true`를 주면 [rerun](https://rerun.io) 뷰어가 열려 카메라 영상과 관절 그래프를 한 화면에서 보여줍니다.

```python
from lerobot.utils.visualization_utils import (
    init_visualization, log_visualization_data, shutdown_visualization
)

init_visualization("rerun", session_name="teleoperation")
# ... 루프 안에서
log_visualization_data("rerun", observation=observation, action=action)
```

### Foxglove

`init_visualization("foxglove", ...)` 로 전환하면 Foxglove로 스트리밍됩니다. ROS 2 토픽과 함께 보고 싶을 때 유용합니다. ([19장](~/lessons/ch19.html))

## 시뮬레이터의 카메라 뷰

실물 카메라가 없어도 배치 감각을 익힐 수 있습니다.

:::task 실습 — 시뮬레이터 카메라 패널
[3D 시뮬레이터](~/sim/index.html)의 **"카메라" 패널**을 켜면 화면 우측에 두 개의 뷰가 나타납니다.

- **손목 뷰** — `gripper_frame_link`(TCP)에 부착된 가상 카메라. 팔을 움직이면 시점이 함께 움직입니다.
- **전역 뷰** — 작업대 위를 비스듬히 내려다보는 고정 카메라.

큐브를 집는 동작을 하면서 **두 뷰만 보고도 작업을 판단할 수 있는지** 확인해 보세요. 손목 뷰에서 큐브가 프레임을 벗어나면, 실물에서도 같은 문제가 생깁니다.
:::

## 카메라 장착 팁

- **손목 카메라는 그리퍼 조(jaw)가 프레임 하단에 살짝 보이도록** 각도를 잡으세요. 그리퍼와 물체의 상대 거리를 정책이 파악할 수 있습니다.
- **전역 카메라는 삼각대나 별도 스탠드**에 고정하세요. 로봇 베이스에 붙이면 팔 진동이 영상에 전달됩니다.
- **조명을 일정하게** 유지하세요. 창가에서 수집한 데이터는 시간대에 따라 밝기가 달라져 정책이 혼란스러워합니다.
- 카메라 USB 케이블을 **관절 사이에 끼이지 않게** 정리하세요. 케이블 장력이 관절 동작을 방해하면 데이터가 오염됩니다.

:::danger 데이터 수집 중 카메라를 움직이지 마세요
50개 에피소드를 수집하는 중간에 카메라를 건드리면, 그 전후 데이터가 **서로 다른 분포**가 되어 학습이 망가집니다. 실수로 건드렸다면 그 시점부터 다시 수집하거나, 처음부터 다시 하는 편이 낫습니다.
:::

## 문제 해결

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 카메라가 검출 안 됨 | 권한 없음 | `sudo usermod -a -G video $USER` |
| 영상이 검게 나옴 | 잘못된 video 인덱스 | `lerobot-find-cameras opencv` 재확인 |
| 프레임이 뚝뚝 끊김 | USB 대역폭 부족 | 다른 포트로 분산, 해상도 낮춤 |
| `VIDIOC_STREAMON` 오류 | 다른 프로그램이 카메라 점유 | 영상 앱·브라우저 탭 종료 |
| 영상이 뒤집혀 나옴 | 카메라 물리 장착 방향 | 물리적으로 회전시켜 장착 |
| 두 카메라 중 하나만 나옴 | 동일 USB 컨트롤러 대역폭 초과 | 포트 분리, MJPEG 카메라 사용 |
| Windows에서 인식 안 됨 | DirectShow 백엔드 문제 | 카메라 드라이버 업데이트 |
