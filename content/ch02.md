## 이 장에서 다루는 것

로봇팔을 다루는 데 반드시 필요한 최소한의 이론입니다. 수식은 **SO-ARM101의 실제 URDF 값**으로만 설명하고, 모든 개념은 [3D 시뮬레이터](~/sim/index.html)에서 슬라이더를 움직여 바로 확인할 수 있게 구성했습니다.

:::task 준비
새 탭에서 [시뮬레이터](~/sim/index.html)를 열고 이 문서와 나란히 놓으세요. "조인트" 탭의 슬라이더를 움직이며 읽으면 이해가 훨씬 빠릅니다.
:::

## 링크와 조인트

로봇팔은 **링크(link, 강체 부품)** 가 **조인트(joint, 관절)** 로 연결된 사슬입니다. SO-ARM101의 사슬은 다음과 같습니다.

```text
base_link
  └─[shoulder_pan]──  shoulder_link
        └─[shoulder_lift]── upper_arm_link
              └─[elbow_flex]── lower_arm_link
                    └─[wrist_flex]── wrist_link
                          └─[wrist_roll]── gripper_link
                                ├─[gripper]── moving_jaw_link
                                └─(fixed)──── gripper_frame_link  ← TCP
```

@fig[link-chain] `so101_new_calib.urdf` 가 정의하는 링크·조인트 사슬. 오른쪽 숫자는 실제 조인트 한계와 서보 ID입니다.

- **조인트가 6개**이므로 6자유도(DOF)입니다. 단, 그리퍼는 물건을 잡는 용도이지 **위치 결정에 기여하지 않으므로**, 공간 자세 결정에 쓰이는 것은 앞의 5개입니다.
- 마지막 `gripper_frame_link`는 조인트가 아니라 **고정 프레임**입니다. 이 지점을 **TCP(Tool Center Point, 툴 중심점)** 라 부르며, "로봇이 어디를 집는가"의 기준이 됩니다.

:::info 5자유도의 의미
공간상의 자세는 위치 3 + 방향 3 = 6자유도입니다. SO-ARM101은 5개뿐이므로 **원하는 위치와 원하는 방향을 동시에 완전히 만족시킬 수는 없습니다.** 보통 위치 3자유도를 우선 맞추고, 방향은 "접근 방향(approach)" 정도만 근사합니다. 시뮬레이터의 IK 모드가 정확히 이렇게 동작합니다.
:::

## 조인트 한계 (Joint Limits)

URDF `so101_new_calib.urdf`에 정의된 실제 값입니다. 이 범위를 넘기면 3D 프린팅 부품이 서로 간섭하거나 서보가 손상됩니다.

| 조인트 | 한국어 | 하한 (rad) | 상한 (rad) | 하한 (°) | 상한 (°) | 가동범위 |
| --- | --- | --- | --- | --- | --- | --- |
| `shoulder_pan` | 어깨 회전 | -1.91986 | 1.91986 | -110.0° | 110.0° | 220° |
| `shoulder_lift` | 어깨 들기 | -1.74533 | 1.74533 | -100.0° | 100.0° | 200° |
| `elbow_flex` | 팔꿈치 | -1.69000 | 1.69000 | -96.8° | 96.8° | 194° |
| `wrist_flex` | 손목 굽힘 | -1.65806 | 1.65806 | -95.0° | 95.0° | 190° |
| `wrist_roll` | 손목 회전 | -2.74385 | 2.84121 | -157.2° | 162.8° | 320° |
| `gripper` | 그리퍼 | -0.174533 | 1.74533 | -10.0° | 100.0° | 110° |

@fig[joint-limits] 각 조인트의 가동범위를 부채꼴로 그린 것. 점선이 0°, 초록 영역이 움직일 수 있는 범위입니다. **URDF 값으로 직접 계산해 그렸습니다.**

:::warn 실물은 더 좁을 수 있습니다
URDF의 한계는 **설계값**입니다. 실제 조립 상태·케이블 배선·카메라 마운트 때문에 물리적 한계가 더 좁아지는 경우가 흔합니다. 특히 `wrist_roll`은 서보 레지스터상 더 돌 수 있어도 **케이블이 감겨 약 ±79° 부근에서 기계적으로 막히는** 사례가 보고됩니다. 처음 구동할 때는 속도를 낮추고 한 관절씩 확인하세요.
:::

## 좌표계와 변환

### URDF의 조인트 정의 읽는 법

URDF의 조인트 한 개는 이렇게 생겼습니다.

```xml
<joint name="elbow_flex" type="revolute">
  <origin xyz="-0.11257 -0.028 0" rpy="0 0 1.5708"/>
  <parent link="upper_arm_link"/>
  <child  link="lower_arm_link"/>
  <axis xyz="0 0 1"/>
  <limit effort="10" velocity="10" lower="-1.69" upper="1.69"/>
</joint>
```

읽는 순서는 이렇습니다.

1. **부모 링크 좌표계**에서 출발한다.
2. `origin`의 `xyz`만큼 **평행이동**하고, `rpy`(roll-pitch-yaw, 고정축 X→Y→Z 순)만큼 **회전**해서 조인트 프레임을 만든다.
3. 그 프레임에서 `axis`(여기선 +Z) 를 중심으로 **조인트 각도 θ만큼 회전**하면 자식 링크 좌표계가 된다.

행렬로 쓰면 다음과 같습니다.

```text
T_parent→child(θ) = Translate(xyz) · RPY(rpy) · RotZ(θ)
```

SO-ARM101은 **모든 조인트의 회전축이 자기 좌표계의 +Z** 이므로 계산이 매우 단순합니다.

### 기준 좌표계

- `base_link` 원점은 베이스 바닥 중심입니다. **+Z가 위쪽**입니다.
- ROS 2에서는 이 관계를 `robot_state_publisher`가 **TF 트리**로 브로드캐스트합니다. RViz2에서 "TF" 디스플레이를 켜면 위 사슬이 그대로 보입니다. ([16장](~/lessons/ch16.html))

## 정기구학 (Forward Kinematics, FK)

> **조인트 각도를 알 때 → TCP가 어디 있는지 구하는 것.**

방법은 위 변환 행렬을 **베이스부터 TCP까지 순서대로 곱하는 것**이 전부입니다.

```text
T_base→tool(q) = T_pan(q1) · T_lift(q2) · T_elbow(q3) · T_wristflex(q4) · T_wristroll(q5) · T_toolfixed
```

TCP의 위치는 결과 행렬의 4번째 열(평행이동 성분)이고, 방향은 왼쪽 위 3×3 회전 성분입니다.

:::task 실습 1 — FK 확인하기
시뮬레이터에서 **"Zero" 프리셋**을 누르고 TCP 좌표를 확인하세요. 그다음 `shoulder_pan` 하나만 +90°로 돌려 보세요.

- TCP의 **높이(z)는 거의 변하지 않고** x·y만 바뀝니다. → `shoulder_pan`이 수직축 회전이기 때문입니다.
- 이번엔 `shoulder_lift`만 움직여 보세요. **z가 크게 변합니다.**

FK는 항상 **해가 하나**입니다. 조인트 각도가 정해지면 TCP는 반드시 한 곳입니다.
:::

파이썬으로 직접 계산해 보고 싶다면 저장소의 `scripts/so101_fk_ik.py`를 실행하세요.

```bash
python scripts/so101_fk_ik.py --fk 0 -30 45 60 0
```

## 역기구학 (Inverse Kinematics, IK)

> **TCP를 여기에 두고 싶을 때 → 조인트 각도를 구하는 것.**

FK와 달리 IK는 어렵습니다.

- **해가 여러 개일 수 있습니다.** (팔꿈치를 위로 꺾어도, 아래로 꺾어도 같은 지점에 닿음)
- **해가 아예 없을 수 있습니다.** (작업영역 밖, 혹은 조인트 한계 때문)
- **특이점(singularity)** 에서는 해가 불안정해집니다. 팔을 완전히 편 자세가 대표적입니다.

@fig[fk-ik] 같은 기구학이지만 방향이 반대입니다. 한쪽은 계산 한 번, 다른 쪽은 반복 탐색입니다.

### 이 강좌에서 쓰는 방법: DLS

시뮬레이터와 `scripts/so101_fk_ik.py`는 **감쇠 최소자승법(Damped Least Squares, Levenberg-Marquardt)** 을 씁니다. 개념은 간단합니다.

1. 현재 자세에서 FK를 계산해 **목표까지의 오차 e**를 구한다.
2. 각 조인트를 아주 조금 움직였을 때 TCP가 얼마나 움직이는지 표로 만든다 → **야코비안 J**.
3. `Δq = (JᵀJ + λ²I)⁻¹ Jᵀ e` 만큼 조인트를 움직인다. λ는 특이점 근처에서 해가 폭주하지 않게 잡아주는 **감쇠 계수**입니다.
4. 오차가 충분히 작아질 때까지 반복한다.

:::task 실습 2 — IK 만져보기
시뮬레이터의 **"IK" 탭**을 켜고 빨간 목표 구(球)를 드래그해 보세요.

1. 팔이 닿는 범위에서는 부드럽게 따라옵니다.
2. 베이스에서 멀리 끌면 팔이 쭉 뻗은 채 **더는 따라오지 못합니다** → 작업영역의 경계입니다. 상태 표시에 "도달 불가"가 뜹니다.
3. 목표를 베이스 바로 위로 끌어 보세요. 해가 여러 개라 팔이 **덜덜 떨리거나 갑자기 자세가 뒤집히는** 현상을 볼 수 있습니다 → 특이점입니다.
:::

:::tip MoveIt 2와의 관계
18장에서 쓸 MoveIt 2는 IK 솔버(KDL/TRAC-IK)와 **충돌 회피 경로 계획(OMPL)** 까지 함께 제공합니다. 여기서 배운 IK는 그 내부에서 벌어지는 일을 이해하기 위한 것입니다.
:::

## 작업영역 (Workspace)

조인트 한계 안에서 TCP가 도달할 수 있는 3차원 공간입니다. SO-ARM101의 대략적인 수치는 다음과 같습니다.

- 베이스 중심에서 TCP까지 **최대 수평 도달 약 48 cm** (URDF 조인트 한계 기준)
- **최대 높이 약 53 cm**
- 좌우 회전 범위 **±110°**
- 실용적인 작업 영역은 이보다 좁습니다. 팔을 거의 다 편 자세는 토크가 부족하고 정밀도도 떨어지므로, **반경 15~30 cm 구간**에서 작업물을 배치하는 것이 안정적입니다.

@fig[workspace-section] 무작위 자세 40만 개를 계산해 (수평거리, 높이) 평면에 찍은 **실제 도달 영역**입니다. 테이블 면 아래로도 계산상 내려가지만 실제로는 책상에 막힙니다.

:::task 실습 3 — 작업영역 그려보기
시뮬레이터의 **"작업영역 표시"** 체크박스를 켜면, 무작위 샘플링으로 도달 가능한 점 구름이 그려집니다. 앞쪽은 넓지만 **베이스 바로 위와 바로 앞 아주 가까운 곳은 구멍이 뚫려 있는 것**을 확인하세요. 실제 작업물을 배치할 때 이 사각지대를 피해야 합니다.
:::

## 서보 각도와 소프트웨어 단위

STS3215 서보는 한 바퀴(360°)를 **0~4095 틱**으로 표현합니다.

```text
1 틱 = 2π / 4096 = 0.00153398 rad = 0.0879°
중위(center) = 2047 또는 2048
```

@fig[tick-scale] 같은 자세를 부르는 세 가지 숫자. LeRobot 로그에 찍히는 값이 각도가 아닌 이유입니다.

:::info 이 숫자를 기억해 두세요
ROS 2 하드웨어 인터페이스에서 RViz 자세와 실물 자세가 어긋날 때 오프셋을 보정하는 공식이 바로 이 값을 씁니다.
`새 offset = 현재 offset + (RViz에 표시된 오차 rad ÷ 0.00153398)` — [17장](~/lessons/ch17.html)에서 다시 나옵니다.
:::

LeRobot은 여기에 한 겹을 더 씌웁니다. 캘리브레이션으로 얻은 각 조인트의 가동범위를 **-100 ~ +100** (그리퍼는 **0 ~ 100**) 으로 정규화해서 다룹니다. 그래서 LeRobot 로그에 찍히는 값은 각도가 아니라 이 정규화 값입니다. 시뮬레이터의 "단위" 토글로 세 가지 표현(도 / 라디안 / LeRobot 정규화)을 나란히 비교할 수 있습니다.

## 정리

| 개념 | 한 줄 정의 | 확인 방법 |
| --- | --- | --- |
| 자유도(DOF) | 독립적으로 움직일 수 있는 관절 수 | 시뮬레이터 슬라이더 6개 |
| 링크/조인트 | 강체 부품 / 그 사이 관절 | URDF 체인 |
| FK | 각도 → TCP 위치 | 항상 해 1개 |
| IK | TCP 위치 → 각도 | 해가 0개·1개·여러 개 |
| TCP | 툴 중심점 = `gripper_frame_link` | 시뮬레이터 좌표 표시 |
| 작업영역 | TCP가 닿는 공간 | 시뮬레이터 점 구름 |
| 특이점 | 자유도를 잃어 IK가 불안정해지는 자세 | 팔을 쭉 폈을 때 |
