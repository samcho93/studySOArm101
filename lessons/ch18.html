18MoveIt 2 모션 플래닝

Setup Assistant로 SRDF를 만들고 OMPL 플래닝, 충돌 회피, Pick&Place를 구현합니다.

시뮬레이터 열기 명령어 생성기

MoveIt 2가 해주는 일#

2장에서 배운 IK는 "TCP를 여기에 두려면 각도가 얼마인가"만 답합니다. MoveIt 2는 그 위에 다음을 얹습니다.

기능설명
IK 솔버KDL / TRAC-IK 등으로 목표 자세의 관절 각 계산
경로 계획OMPL(RRTConnect, RRT*, PRM…)로 충돌 없는 궤적 탐색
충돌 검사자기 충돌(self-collision) + 환경 장애물
궤적 시간 최적화속도·가속도 한계를 지키는 타이밍 부여
실행joint_trajectory_controller로 전송

데모 실행 (Mock 하드웨어)#

터미널 하나면 됩니다. demo.launch.py가 컨트롤러 스택을 내부에서 자동으로 띄웁니다.

bash
ros2 launch so_arm101_moveit_config demo.launch.py

RViz 창이 열리면:

  1. MotionPlanning 패널에서 **Planning Group → manipulator**
  2. **Start State → <current>, Goal State → extended**
  3. Plan 클릭 → 주황색 궤적 미리보기
  4. Execute 클릭 → 실행

사용 가능한 프리셋 자세: **open, zero, extended, rest**

RViz 첫 실행이 느린 건 정상입니다

MoveIt은 시작 시 URDF 모델, 충돌 검사 플러그인, 기구학 솔버를 모두 로드합니다. 첫 실행에 약 10초 걸립니다.

MotionPlanning 패널 사용법#

Planning 탭#

항목설명
Planning Group제어할 관절 그룹. SO-ARM101은 manipulator
Start State시작 자세. 보통 <current>
Goal State목표 자세. 프리셋 또는 <random valid>
Plan경로만 계산 (실행하지 않음)
Execute계산된 경로 실행
Plan & Execute한 번에

플래닝 파라미터#

파라미터의미권장값
Planning Time최대 탐색 시간(초)5 → 실패 시 10
Planning Attempts재시도 횟수10
Velocity Scaling속도 배율 (0~1)첫 테스트 0.3
Acceleration Scaling가속도 배율 (0~1)첫 테스트 0.3
첫 테스트는 반드시 0.1~0.3으로

속도와 가속도를 낮추면 문제가 생겼을 때 대응할 시간이 생깁니다. 실기에서는 특히 중요합니다.

Scene Objects 탭#

  • 장애물(Box / Sphere / Cylinder)을 추가해 충돌 검사에 반영
  • 장면(scene) 가져오기 / 내보내기
  • MoveIt이 자동으로 장애물을 피해 경로를 계획합니다

Stored States 탭#

  • 자주 쓰는 자세를 저장
  • 기본 제공: open, zero, extended, rest

네 가지 목표 지정 방법#

방식 A — 인터랙티브 마커 드래그 (권장)#

  1. 3D 뷰에서 팔 말단의 인터랙티브 마커(색색의 화살표와 원환)를 찾습니다.
  2. 화살표를 끌면 위치 이동, 원환을 끌면 방향 회전입니다.
  3. MoveIt이 실시간으로 IK를 풀어 관절 각을 갱신합니다.
  4. Plan 으로 주황색 궤적을 확인합니다.
  5. 확인 후 Execute.
드래그가 버벅일 때

rest 프리셋 자세에서 출발해 드래그하면 훨씬 부드럽습니다. 특이점 근처(팔을 완전히 편 상태)에서 시작하면 IK가 불안정해집니다.

방식 B — 프리셋 자세#

  1. Query Goal State 드롭다운 → open / extended / rest 등 선택
  2. Update 클릭
  3. Plan → Execute

방식 C — 관절 각 직접 입력#

  1. Query Goal State → Joints 탭
  2. 각 관절 슬라이더로 목표 각도 설정
  3. 관절 범위는 15장 한계표 참고

방식 D — 무작위 유효 목표#

Random Valid 버튼을 누르면 도달 가능한 임의의 자세가 생성됩니다. Plan → Execute.

작업영역 확인용으로 좋습니다

Random Valid를 여러 번 눌러 보면 이 로봇이 실제로 어디까지 갈 수 있는지 감이 잡힙니다.

안전 수칙#

실기에서 MoveIt을 실행할 때
  1. 첫 사용은 속도를 낮추세요 — Velocity / Acceleration 0.1~0.3
  2. 긴급 정지 — 언제든 Ctrl+C로 프로그램을 종료하거나 전원을 뽑으세요
  3. 관절 한계 — MoveIt은 joint_limits.yaml 범위를 넘지 않지만, 설정이 정확해야 합니다
  4. 공간 확보 — 실행 전 팔 주변에 충분한 공간이 있는지 확인하세요

MoveIt 설정 개요#

SRDF (Semantic Robot Description Format)#

URDF가 "물리 구조"라면 SRDF는 "의미론적 정보"입니다.

xml
<robot name="so_arm101">
  <!-- 플래닝 그룹 -->
  <group name="manipulator">
    <chain base_link="base_link" tip_link="gripper_frame_link"/>
  </group>

  <group name="gripper">
    <joint name="gripper"/>
  </group>

  <!-- 미리 정의된 자세 -->
  <group_state name="rest" group="manipulator">
    <joint name="shoulder_pan"  value="0"/>
    <joint name="shoulder_lift" value="-1.68"/>
    <joint name="elbow_flex"    value="1.60"/>
    <joint name="wrist_flex"    value="0.75"/>
    <joint name="wrist_roll"    value="0"/>
  </group_state>

  <group_state name="extended" group="manipulator">
    <joint name="shoulder_pan"  value="0"/>
    <joint name="shoulder_lift" value="0.35"/>
    <joint name="elbow_flex"    value="-0.45"/>
    <joint name="wrist_flex"    value="0.15"/>
    <joint name="wrist_roll"    value="0"/>
  </group_state>

  <!-- 엔드 이펙터 -->
  <end_effector name="eef" parent_link="gripper_frame_link" group="gripper"/>

  <!-- 충돌 검사 제외 쌍 (인접 링크는 항상 붙어 있으므로) -->
  <disable_collisions link1="base_link"      link2="shoulder_link"  reason="Adjacent"/>
  <disable_collisions link1="shoulder_link"  link2="upper_arm_link" reason="Adjacent"/>
  <disable_collisions link1="upper_arm_link" link2="lower_arm_link" reason="Adjacent"/>
  <disable_collisions link1="lower_arm_link" link2="wrist_link"     reason="Adjacent"/>
  <disable_collisions link1="wrist_link"     link2="gripper_link"   reason="Adjacent"/>
  <disable_collisions link1="gripper_link"   link2="moving_jaw_so101_v1_link" reason="Adjacent"/>
</robot>

Setup Assistant로 직접 만들기#

기존 설정을 수정하거나 처음부터 만들려면:

bash
ros2 launch moveit_setup_assistant setup_assistant.launch.py

진행 순서:

  1. Load URDF — so_arm101.urdf.xacro 로드
  2. Self-Collisions — "Generate Collision Matrix" 클릭 (샘플링 밀도 기본값 OK)
  3. Planning Groups — manipulator 그룹 생성, Kinematic Chain을 base_link → gripper_frame_link로 설정, 솔버는 KDLKinematicsPlugin
  4. Robot Poses — rest, extended, zero, open 정의
  5. End Effectors — gripper_frame_link 기준으로 정의
  6. ros2_control URDF Modification — 이미 xacro에 있으므로 건너뜀
  7. Controllers — joint_trajectory_controller를 manipulator 그룹에 연결
  8. Generate Package — so_arm101_moveit_config로 저장
컨트롤러 이름이 맞아야 합니다

moveit_controllers.yaml의 컨트롤러 이름이 17장의 controllers.yaml과 정확히 일치해야 Execute가 동작합니다. 여기서 실수하면 "Plan은 되는데 Execute를 눌러도 안 움직이는" 증상이 납니다.

yaml
# moveit_controllers.yaml
moveit_controller_manager: moveit_simple_controller_manager/MoveItSimpleControllerManager

moveit_simple_controller_manager:
  controller_names:
    - joint_trajectory_controller

  joint_trajectory_controller:
    type: FollowJointTrajectory
    action_ns: follow_joint_trajectory
    default: true
    joints:
      - shoulder_pan
      - shoulder_lift
      - elbow_flex
      - wrist_flex
      - wrist_roll
      - gripper

코드로 제어하기#

Python (moveit_py)#

python
import rclpy
from rclpy.node import Node
from moveit.planning import MoveItPy

rclpy.init()
so101 = MoveItPy(node_name="so101_moveit_py")
arm = so101.get_planning_component("manipulator")

# 1) 프리셋 자세로
arm.set_start_state_to_current_state()
arm.set_goal_state(configuration_name="extended")
plan = arm.plan()
if plan:
    so101.execute(plan.trajectory, controllers=[])

# 2) TCP 목표 자세로
from geometry_msgs.msg import PoseStamped

target = PoseStamped()
target.header.frame_id = "base_link"
target.pose.position.x = 0.22
target.pose.position.y = 0.05
target.pose.position.z = 0.15
target.pose.orientation.w = 1.0

arm.set_start_state_to_current_state()
arm.set_goal_state(pose_stamped_msg=target, pose_link="gripper_frame_link")
plan = arm.plan()
if plan:
    so101.execute(plan.trajectory, controllers=[])

Pick & Place 구현하기#

전형적인 픽앤플레이스는 다음 단계로 구성됩니다.

text
1. 홈 자세로 이동
2. 그리퍼 열기
3. 물체 위 10cm (pre-grasp) 로 이동
4. 물체까지 직선 하강 (Cartesian path)
5. 그리퍼 닫기
6. 직선 상승
7. 목표 위 10cm 로 이동
8. 하강
9. 그리퍼 열기
10. 상승 → 홈

직선 이동(Cartesian path) 은 일반 플래닝과 다릅니다.

python
waypoints = []
pose = current_pose()
pose.position.z -= 0.10        # 10cm 직선 하강
waypoints.append(pose)

fraction, trajectory = arm.compute_cartesian_path(
    waypoints, eef_step=0.005, jump_threshold=0.0
)
if fraction > 0.95:            # 95% 이상 성공했을 때만 실행
    so101.execute(trajectory, controllers=[])
왜 직선 경로가 필요한가

일반 플래닝(OMPL)은 충돌만 피하면 어떤 경로든 만듭니다. 물체를 집으러 내려갈 때 팔이 옆으로 휘면 물체를 건드려 쓰러뜨립니다. 파지 직전·직후는 반드시 직선 경로를 쓰세요.

문제 해결#

증상원인해결
Motion planning start tree could not be initialized시작 상태가 관절 한계 초과아래 상세 참고
같은 오류 + 자기 충돌시작 자세에서 자기 충돌아래 상세 참고
Execute 후 안 움직임컨트롤러 비활성ros2 control list_controllers 확인
경로가 떨리고 매끄럽지 않음플래너 특성Planner를 RRTConnect로, Planning Time을 10초로
목표에 도달 못 함작업영역 밖Random Valid로 도달 가능 범위 확인
RViz가 느림충돌 메시 복잡프리미티브 충돌 형상 사용

Motion planning start tree could not be initialized 상세#

원인은 보통 둘 중 하나입니다.

1) 관절이 한계를 벗어남

로그에서 FixStartStateBounds 출력을 확인하세요. 기본 허용 오차는 0.3 rad이며, 이 범위 안의 초과는 자동 보정됩니다. 그 이상이면:

  • start_state_max_bounds_error를 늘리거나
  • 서보 position_offset을 다시 잡으세요 (17장)

2) 시작 상태에서 충돌

로그에서 FixStartStateCollision 출력을 확인하세요. Unable to find a valid state nearby가 뜨면 현재 자세에 자기 충돌이 있습니다.

  • 팔이 접힌 자세(예: 그리퍼가 어깨에 닿음)일 가능성
  • 오프셋이 잘못되어 실제와 다른 자세로 인식되는 경우

팔을 손으로 펴고 다시 시도하거나, 오프셋을 조정하세요.
